## 一、定位與範圍

### 1.1 定位

- **完全獨立**：新開 repo，不引用 `campus-toolkit` 任何程式碼；主程式僅以固定常數 `MARKET_URL` 呼叫其公開 API。
- **協議相容**：主題 JSON 遵循主程式側 `CSS主題個性化規劃書.md` §2 的 33 鍵 Schema，任何團隊、學校只要遵守同一份規格即可串接。
- **公開瀏覽**：搜尋、預覽、下載 JSON、複製 JSON **免登入**。
- **登入才需要**：安裝到主系統（寫入帳號欄位）、投稿。
- **審核制**：所有投稿須經管理員上架後才會出現在公開列表。

### 1.2 GAS 版的落差與本文件的調整

| 項目 | GAS 版 | 本文件 |
|---|---|---|
| 跨域 `install_url` 一鍵安裝協議 | 必需（不同域、localStorage 不通） | **不需要**——改為主系統 `/theme/install` 頁承接（見 §5.3） |
| HTTP 狀態碼 | 恆 200，靠拋 Error 回 500 判斷 | 原生狀態碼（404 / 400 / 401） |
| CORS | 瀏覽器無法 fetch，全部走 `UrlFetchApp` | 主程式以 **server-side fetch** 取回，不受 CORS 影響；市集公開 API 亦可直接加 `Access-Control-Allow-Origin` |
| 資料層 | Google 試算表 | Firestore |
| 定位路由 | `?api=` / `?page=` 參數式 | Next.js App Router 路徑式 |
| 審核 Email 通知 | MailApp | **第一期不做**（決策，見 §8.4） |
| 登入 | 僅帳密 | 帳密 + Google 登入 |
| 內建主題 | 8 套硬編碼於 `theme_manager` | **不入庫**，但提供「複製 JSON」供編修（見 §11） |

## 二、主題 JSON Schema

**唯一規格來源**：`campus-toolkit/docs/CSS主題個性化規劃書.md` §2。

市集 repo 複製一份 `src/lib/theme-package.ts`（型別、33 鍵白名單、值驗證 regex、`validateThemePackage`），內容與主程式逐條一致。同步機制：

1. Schema 變更只在主程式側文件修改，市集依該文件更新其複本。
2. 規劃書附錄 A 提供 **10 組合法 / 非法 JSON 案例**（見本文件附錄 A），兩邊驗證實作都必須通過同一組案例。
3. `schema_version` 目前固定 `1`；未來不相容變更時遞增，兩邊各自保留對舊版的相容判斷。

**必要欄位**：`id`、`name`、`colors`；**本體上限** 50KB；**核心 18 鍵缺值補預設**；**未知 `colors` 鍵一律拒絕**。

## 三、資料層（Firestore）

### 3.1 `themes` collection

文件 ID ＝ 主題 id 本身（`market:{uuid}`），便於單點取回。

| 欄位 | 型態 | 必填 | 說明 |
|---|---|---|---|
| `id` | string | 是 | `market:{uuid}`，伺服端重簽產生 |
| `name` | string | 是 | 顯示名稱，≤ 40 |
| `author` | string | 否 | 作者姓名，≤ 40 |
| `authorEmail` | string | 否 | 投稿聯絡信箱，≤ 100 |
| `authorUrl` | string | 否 | ≤ 200，`https://` 或空 |
| `description` | string | 否 | ≤ 300 |
| `tags` | string[] | 否 | ≤ 8 個，每項 ≤ 12 |
| `version` | string | 是 | 語意化版本，如 `1.2.0` |
| `schema_version` | number | 是 | 固定 `1` |
| `colors` | map | 是 | 33 鍵的 map（**存 map 而非 JSON 字串**，省 parse 且可欄位操作） |
| `preview` | map | 是 | `{dot, background, primary}` |
| `status` | string | 是 | `審核中` / `已上架` / `已下架` / `被拒絕` |
| `downloads` | number | 是 | 下載計數，`FieldValue.increment(1)` |
| `ownerId` | string | 是 | 投稿者 uid |
| `reviewNote` | string | 否 | 管理員備註（拒絕原因） |
| `createdAt` | timestamp | 是 | 建立時間 |
| `updatedAt` | timestamp | 是 | 最後變更 |
| `publishedAt` | timestamp | 否 | 上架時間（僅 `已上架` 有值，列表排序鍵） |

**索引**：單欄位等值查詢（`status == "已上架"`）沿用既有單欄位索引即可；若需 `status + publishedAt` 複合排序而回 `FAILED_PRECONDITION`，照錯誤訊息提供的連結建立複合索引（`docs/資料庫讀取規範.md` §4）。

## 四、查詢策略

### 4.1 公開列表

```
第一期（建議）：摘要快取 + 前端搜尋 / 標籤 / 分頁
```

- `GET /api/themes` 回傳**不含 `colors` 的摘要陣列**（`id/name/author/description/tags/version/downloads/preview/status/publishedAt`）。
- 全部 `status == "已上架"` 的摘要（每筆約 300B，200 筆約 60KB）以 `cachedListRead` 快取，前端做中文任意位置搜尋、標籤過濾、分頁。
- **理由**：Firestore 無 substring 查詢，中文任意位置包含只能在前端做。此模式與主程式「帳號清單整表抓回＋前端分頁與搜尋」的既有先例一致（`docs/資料庫讀取規範.md` §5 已明列為「刻意保留」的例外）。
- 失效：市集管理端任何變更成功後呼叫 `invalidateAdminListCache()`（`bumpCacheEpoch()`）。市集是獨立系統，bump epoch 不影響主程式。

**資料量超過約 1,000 筆已上架主題時**改第二期：

```
where("status", "==", "已上架")
  + orderBy("publishedAt", "desc")
  + limit(20) + startAfter(cursor)
```
搜尋改為 `keywords` array 欄位（名稱／描述／標籤的中文二元組）＋ `array-contains`，或引入第三方案（Meilisearch / Typesense）。

### 4.2 詳情

`GET /api/themes/{id}` → 單點 `.doc(id).get()`（**不存在＝0 讀**），回完整 `ThemePackage` + meta。

### 4.3 下載計數

`POST /api/themes/{id}/download` → `increment(1)`，**best-effort**（無法防刷，文件明示僅供參考指標）。詳情頁展示、列表摘要帶 `downloads`。

## 五、API 一覽

### 5.1 市集側

| 端點 | 方法 | 認證 | 回傳 |
|---|---|---|---|
| `/api/themes` | GET | 公開 | `{ ok, total, page, limit, themes: [摘要] }` |
| `/api/themes/{id}` | GET | 公開 | `{ ok, theme: ThemePackage, meta }` |
| `/api/themes/{id}/download` | POST | 公開 | `{ ok }` |
| `/api/themes` | POST | 會員 | 投稿，回 `{ ok, id }`（`status=審核中`） |
| `/api/themes/{id}` | PATCH | 作者 / 管理員 | 更新 `version` / `colors` / meta |
| `/api/themes/{id}` | DELETE | 管理員 | 下架或刪除 |
| `/api/admin/themes` | GET | 管理員 | 三狀態列表（含 `審核中`） |
| `/api/admin/themes/{id}/review` | POST | 管理員 | `{ action: "publish" \| "unpublish" \| "reject", note? }` |
| `/api/admin/members` | GET / POST / PATCH | 管理員 | 會員管理 |
| `/api/auth/login` | POST | — | 帳密登入 |
| `/api/auth/google` | POST | — | Google 登入 |
| `/api/auth/logout` | POST | — | 登出 |
| `/api/auth/me` | GET | 會員 | `{ ok, role, email, name }` |
| `/api/settings` | GET | 公開 | 公開設定（系統名稱、開關） |

**錯誤格式**（沿用 GAS）：`{ ok: false, msg: "…" }`；狀態碼：400 驗證失敗、401 未登入、403 權限不足、404 不存在。

### 5.2 主程式側取回端點

`campus-toolkit/src/app/api/market/themes/[id]/route.ts`（新增）：

```
GET /api/market/themes/{id}
  → server fetch(`${MARKET_URL}/api/themes/${encodeURIComponent(id)}`)
  → 檢查：網域必須完全等於 MARKET_URL 常數（不接受使用者提供的網址）
  → 檢查：狀態碼 200、Content-Length ≤ 50KB、可 JSON.parse
  → 檢查：validateThemePackage(raw, { mode: "install" })（只允許 market:）
  → 回 { ok: true, theme }
```

- `MARKET_URL` 是**寫死在程式中的常數**（GAS 決策 #9：不設設定欄位），透過環境變數 `MARKET_URL` 覆寫以便測試，預設值指向正式市集。
- 失敗一律回 400 + 中文訊息，前端降級到預設主題。

### 5.3 一鍵安裝協議（同域簡化版）

GAS 因跨域才需要 `install_url` 回跳協議；本架構主程式與市集雖然不同網域，但**安裝動作全部在主程式頁面執行**，因此大幅簡化：

```
① 使用者在市集詳情頁點「安裝到數位校園工具箱」
     │
     ├─ 已登入市集 → 先 POST /download（計數），產生連結
     ├─ 未登入市集 → 按鈕變「登入後安裝」→ /login?next=/themes/{id}
     │
② 連結格式（對外公開、可複製分享）：
     {主程式網址}/theme/install?market={encodeURIComponent(MARKET_URL)}&id={themeId}
     │
③ 主程式 /theme/install 頁（公開可開，但安裝需登入）
     │  - 讀取 id（market 參數僅允許等於常數 MARKET_URL，否則忽略）
     │  - GET /api/market/themes/{id}（伺服端 fetch，免 CORS、免使用者 token）
     │  - installTheme(pkg) → 寫入 users.cssThemeId（防抖）→ 進已安裝清單
     │  - 未登入 → 顯示「登入後安裝」按鈕，登入後回跳本頁
     │  - 成功 → 顯示「已安裝並套用」＋「前往個性化主題」
④ 無安裝需求的外部訪客
     → 詳情頁提供「複製安裝連結」「複製 JSON」「下載 JSON」
```

> `market` 參數**不可信**：主程式只認環境變數 `MARKET_URL`，收到的 `market` 參數僅做比對提示，不作為 fetch 目標（防止釣魚網址注入）。

## 八、投稿 → 審核 → 上架

### 8.1 流程

```
使用者在 /submit 送出（session + CSRF token）
   │
   ├─ 驗證：validateThemePackage(raw, { mode: "submit" })
   │        33 鍵白名單、值 regex、≤50KB、必要欄位
   │   ├─ 失敗 → 逐項回傳錯誤（不清空表單）
   │   └─ 成功
   │        ├─ 伺服端重簽 id = market:{uuid}（覆蓋原本的 custom: / imported:）
   │        ├─ ownerId = session.uid；authorEmail 優先取 session.email（可覆寫）
   │        ├─ status = 審核中；createdAt = now
   │        ├─ 寫入 themes（1 寫）
   │        └─ 寫入 themeSubmissions（1 寫，action=投稿）
   │
   ▼
管理員 /admin → 審核列表
   ├─ 上架 → status=已上架、publishedAt=now（2 寫）
   ├─ 下架 → status=已下架
   ├─ 拒絕 → status=被拒絕 + reviewNote（拒絕原因必填）
   └─ 每個動作寫入 themeSubmissions（1 寫）
   └─ invalidateAdminListCache()
```

### 8.2 限流

- 同一 `ownerId` **24 小時內 ≤ `dailySubmitLimit`（預設 3）件**。
- 實作：查 `themeSubmissions` where `ownerId == uid` and `action == "投稿"` and `createdAt >= now - 24h`，`limit` 為 `dailySubmitLimit + 1`（多取 1 筆判斷是否已滿）。回傳 429 + 「今日投稿額度已用完，請明天再試」。
- 以帳號計（非 IP），比照 GAS §7.3。

### 8.3 作者後續更新

作者對自己的 `已上架` / `被拒絕` 主題可 `PATCH`（改 `colors` / `meta`）：
- `已上架` → 更新後 `status` 回到 `審核中`（需重新審核）
- `被拒絕` → 更新後回 `審核中`

### 8.4 通知

**第一期不做 Email 通知**（決策）。管理結果僅顯示於：
- 審核後台列表的 `reviewNote`
- 會員後續可在 `/account` 查看自己主題的狀態（選用功能，列第二期）

## 九、會員與權限

### 9.1 Session

比照主程式 `src/lib/session-token.ts` 的精簡版：

- JWT（`jose`）存 HttpOnly + Secure + SameSite=Lax cookie，有效期 2 小時
- payload：`{ uid, role, email, name, jti, exp }`；`jti` 寫入 `sessions` collection 供撤銷
- 改密碼 / 重設密碼 → `tokenVersion` + 1（所有舊 token 失效）
- POST 一律要求一次性 CSRF token（`nonce`，伺服端快取 10 分鐘）

### 9.2 密碼

- 雜湊：`salt:SHA256`（沿用 GAS 與主程式慣例；若改 `bcryptjs` 更佳，第二期評估）
- 強度：≥ 8 字元且含大寫、小寫、數字
- 登入失敗連續 5 次 → 鎖定 15 分鐘（記錄於 `settings/market` 或 `members.lockedUntil`）

### 9.3 Google 登入

- 使用 Google Identity Services（GIS）`accounts.google.com/gsi/client`，與主程式 `src/app/api/auth/google/route.ts` 同思路
- 流程：前端 `google.accounts.id.initialize` → 取得 credential JWT → 後端驗證簽章與 `aud`（環境變數 `GOOGLE_CLIENT_ID`）→ 依 `sub` 找 `members.googleSub`
  - 找得到 → 直接登入
  - 找不到但 `email` 已綁定 → 綁定 `sub`
  - 都沒有 → **拒絕**（初期不開放自助註冊；訊息「此 Google 帳號尚未開通市集會員，請洽管理員」）
- 會員建立時可由管理員預先填 `googleSub` 或 `email` 以便綁定
- CORS / CSP：`script-src` 與 `frame-src` 需放行 `https://accounts.google.com`（與主程式 `src/proxy.ts:30,40` 同規格）

### 9.4 角色

| 角色 | 權限 |
|---|---|
| 會員（`member`） | 瀏覽、下載、投稿、管理自己的主題與帳號 |
| 管理員（`admin`） | 以上全部 ＋ 審核、上下架、會員管理、系統設定 |

## 十、安全

| 項目 | 措施 |
|---|---|
| 取回網址 | `MARKET_URL` 為固定常數（環境變數覆寫僅供測試）；只允許 `https://`；**不接受使用者提供的網址作為 fetch 目標** |
| 體積 | 本體 ≤ 50KB（投稿端與取回端都檢查） |
| Schema | 雙邊驗證：投稿端 `mode:"submit"`、主程式取回端 `mode:"install"`；未知 `colors` 鍵一律拒絕 |
| CSS 注入 | 值白名單 regex，禁 `;` `{` `}` `<` `>` `url(` `expression(` `@import` |
| XSS | 主題 JSON 只以 `setProperty` 注入 CSS 變數，**不插入 HTML**；所有動態文字走 React 自動跳脫 |
| CSRF | 全部 POST 帶一次性 `nonce` |
| 限流 | 投稿 24h 3 件；登入失敗 5 次鎖 15 分鐘 |
| 權限 | 審核、上下架、會員管理一律伺服端 `role == "admin"` 檢查，不信任前端隱藏 |
| 稽核 | 投稿與審核全部寫 `themeSubmissions`；登入寫 `lastLoginAt` / `loginCount` |
| 內容審查 | 所有主題上架前須經管理員審核 |
| CSP | 與主程式同規格：`style-src 'self' 'unsafe-inline'`（33 鍵 inline 變數需要）、`script-src` 加 nonce、`connect-src` 含 Google |
| 下載計數 | best-effort，文件明示不防刷 |

## 十一、內建 10 套主題的處理

**決策：不入庫。**

- `themes` collection **只存 `market:`**；`builtin:` 不建立文件。
- 市集首頁提供「**內建主題**」分頁／區塊，展示 10 張卡片（資料來源＝市集 repo 內一份靜態 `builtin-themes.json`，內容與主程式 `src/lib/themes.ts` 逐條相同）。
- 每張卡片的動作**只有「複製 JSON」與「下載 JSON」**，不提供安裝（主程式本來就有）、不計下載數、不進搜尋的下載排行。
- 卡片標示「內建」徽章，與「市集」來源區分。
- **用途**：使用者複製內建 JSON 後，可貼到主程式 `/theme/studio` 或市集 `/studio` 當基底修改，做出自己的主題再投稿。
- 同步機制：主程式 10 套若有異動，依主程式側文件 §2 的 Schema 更新市集 repo 的 `builtin-themes.json`（異動頻率極低）。
