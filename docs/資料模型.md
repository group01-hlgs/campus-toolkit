# 資料模型（v2 定稿）

本文件為資料表與權限模型的唯一規格來源。舊模型（`students`／`parents`／`staff`／`admins`／`roster` 五個集合）已全面廢棄，資料備份後清除。

## 架構總覽

兩層模型：

1. **使用者帳號 1 張表**：無週期、永久。回答「這個人能否登入、怎麼登入」。兩階段驗證設置於此層。
2. **身分名冊 4 張表**（學生、家長、教職員、管理員）：以學年度、學期為小週期。回答「登入後的使用者以何種身分操作與使用功能」。

```
users（帳號，1筆/人）
  └─ uid ──> rosterStudents / rosterParents / rosterStaff / rosterAdmins
              （每期每身分 0~1 筆）
```

## 表 1：使用者帳號 `users`

`doc id = uid`。系統欄位 `createdAt`、`updatedAt`（非業務欄位），安全技術欄位 `lockIp`（鎖定綁定來源 IP，防換 IP 鎖號）。

| 欄位 | 鍵名 | 型別 | 說明 |
|---|---|---|---|
| 電子郵件地址 | `email` | string | 選填、**全站唯一**（小寫正規化）。登入識別＋2FA 收信；**與帳號至少填一個** |
| 帳號 | `account` | string | 選填、**全站唯一**。登入識別；**與電子郵件至少填一個** |
| 密碼 | `passwordHash` | string | bcrypt cost 12。**密碼只在這一層**，名冊不存密碼 |
| 2FA驗證 | `twoFactor` | enum | `off` / `email_notify` / `email_otp` / `totp`。實作附欄：`otpHash`、`otpExpiresAt`、`otpSentAt`（驗證碼暫存）、`totpLastCode`、`totpLastUsedAt`（防重放）、`totpFail`、`totpLockedUntil` |
| TOTP密鑰 | `totpSecret` | string | Base32 |
| 姓名 | `name` | string | 帳號層姓名（建檔預設值；顯示以名冊姓名為準） |
| 登入紀錄 | `loginRecords` | number[] | epoch ms，新→舊，最多 50 筆。最後登入＝`loginRecords[0]` |
| 登入方式 | `lastLoginMethod` | string | `password` / `google` + `email_otp` / `totp` / `email_notify` |
| 登入次數 | `loginCount` | number | |
| CSS主題ID | `cssThemeId` | string | |
| 已安裝主題清單 | `installedThemes` | string | JSON 陣列字串 |
| 鎖定至 | `lockedUntil` | number | epoch ms，0＝未鎖 |
| 失敗次數 | `failedAttempts` | number | 達門檻寫入鎖定至 |
| tokenVersion | `tokenVersion` | number | 改密碼＋1，舊 session 全數失效 |
| 須先改密碼 | `mustChangePassword` | boolean | 管理員代設**預設密碼**時＝`true`（建立帳號、重設他人密碼），該員登入後由全螢幕遮罩要求先由本人修改；本人改密或一次性連結重設後＝`false`。缺省（舊帳號、Google 建立的帳號）＝不強制 |
| **慣用身分** | `preferredRole` | UserRole（保留） | 多身分時登入預設進入的身分。未設定或值不在候選內＝進選擇頁 |
| **狀態** | `status` | enum | `有效` / `無效`（介面顯示「停用」）。缺省＝有效，**≠ 有效即擋登入** |

**識別規則**：帳號無週期，只有「建立／刪除」與「有效／無效」。辨識鍵＝電子郵件地址或帳號
（至少填一個，另一欄可留空；兩者都填須指向同一帳號）。有值才查重，空值不參與唯一檢查。
無電子郵件的帳號仍可用「帳號＋密碼」登入；但忘記密碼信、Email OTP、登入通知與 Google
登入需信箱，此類帳號改由管理員重設密碼、2FA 用 TOTP。

## 表 2～5：身分名冊 4 張

集合：`rosterStudents`、`rosterParents`、`rosterStaff`、`rosterAdmins`
`doc id = ${uid}_${學年度}_${學期}`（一 uid 一期一表最多一筆）

### 共同欄位

| 欄位 | 鍵名 | 型別 | 說明 |
|---|---|---|---|
| 狀態 | `status` | `有效` / `無效`（介面顯示「停用」） | **擋該身分能否使用** |
| 電子郵件地址 | `email` | string | 該期該身分的信箱（展示／搜尋）；帳號無信箱則留空 |
| 帳號 | `account` | string | 該期該身分對應的**帳號名**（展示與銜接用）；建立時寫入，舊資料可能留空（靠 `email` 比對） |
| 姓名 | `name` | string | 該期該身分的姓名（**顯示以此為準**） |
| 學年度 | `academicYear` | number | 民國年 |
| 學期 | `semester` | 1 \| 2 | |

系統／關聯欄位：`uid`（連回使用者帳號）、`createdAt`、`updatedAt`。
帳號已刪除而條目保留時，`uid` 已查無使用者文件（稱「孤兒列」，見下方「孤兒條目與銜接」）。

### 各表專屬欄位

| 表 | 專屬欄位（鍵名） |
|---|---|
| **學生** `rosterStudents` | 學號 `studentId`、年級 `grade`、班級代碼 `classCode`、班級名稱 `className`、座號 `seatNo`、班號 `rollNo` |
| **家長** `rosterParents` | 學生姓名 `studentName`、學生電子郵件地址 `studentEmail`、學號 `studentId`、年級 `grade`、班級代碼 `classCode`、班級名稱 `className`、座號 `seatNo`、班號 `rollNo`、關係 `relation` |
| **教職員** `rosterStaff` | 屬性 `attribute`（教師/兼導師/兼行政/職員）、單位 `unit`、職稱 `title`、班級代碼 `classCode`、班級名稱 `className` |
| **管理員** `rosterAdmins` | 屬性 `attribute`（一般/超級，**「超級」只有超級管理員可以指派**）、指定功能模組 `modules`（陣列，**可選**：只存實際指定的內容、系統不自動補值；未指定＝除基本模組「系統設定」外無可用功能模組） |

### 功能模組選項（管理員）

`users` 使用者帳號管理、`roster` 身分名冊管理、`settings` 系統設定、`schoolSettings` 學校基本設定、`activity` 稽核紀錄。
超級管理員＝全開（權限由 `attribute` 判定，與 `modules` 內容無關）；
一般管理員＝僅被指定模組（`modules` 為可選欄位，名冊表單／批次只存使用者實際指定的內容，
未指定＝除基本模組外無可用模組，系統不代為補值）。
基本模組 `settings` 系統設定：入口對每位管理員（含一般屬性）一律顯示、不需指派；
實際可讀寫的設定項目**僅超級管理員**（`hasSettingsManage`），
一般管理員與其他身分頁內顯示「尚無可用設定項目」（可用功能日後再收斂）。
超級專屬模組 `schoolSettings` 學校基本設定：**僅超級管理員**可用——
不列入名冊表單的可指派清單（`SUPER_ONLY_ADMIN_MODULES`），
即使名冊存有該代碼也不授予，管理員首頁卡片只對超級屬性顯示。
（舊代碼 `roles`＝身分管理已併入 `roster`，舊資料仍會對應到 `roster`，不失權。
舊代碼 `account`＝個人頁，個人頁已不需權限，故不再對應任何模組。）

### 管理員屬性的層級守門

「超級」屬性＝全站最高權限，**只有超級管理員可以指派或變更**
（`dal.checkAdminAttribute` → `roster.adminAttributeGuard`，非超級一律回 403）：

- 不得把屬性設為「超級」：名冊單筆建立／編輯、名冊批次新增與修改、
  帳號「同時建立身分」與帳號批次建立皆會擋（`/api/auth/me` 回傳 `adminAttribute`，
  管理員表單只對超級操作者顯示「超級」選項，表單端同步擋）。
- 不得修改、停用、刪除**既有的超級條目**（含批次列）。
- `POST /api/admin/create` 一律建立超級管理員，故非初始建立分支**須由超級管理員執行**
  （一般管理員無法藉此建出超級）。

另擋「動最後一位超級管理員」（`roster.lastSuperGuard`，以及帳號層的 `accountStatusGuard`
與名冊批次覆蓋模式的保留清單）：降級／停用／刪除最後一位超級前，須先有另一位超級管理員——
否則系統將無人可再指派超級（系統設定、學校基本設定無人可改）。

孤兒條目銜接同受管制：孤兒中若含超級條目，`/api/admin/roster/link` 與帳號頁的
「同時建立身分」／批次建立（`linkOrphanEntries`、`moveEntriesUid` 的 `allowSuper`）
非超級一律 403 或略過超級列，避免經銜接間接取得超級。

若既有資料**當期完全沒有超級管理員**，上述守門會讓「指定超級」也無從在介面完成
（此狀態下系統設定本就已不可用）：請至 Firestore Console 將某一筆
`rosterAdmins/{uid}_{學年度}_{學期}` 的 `attribute` 改為「超級」，
或執行 `scripts/reset-users-roster.mjs` 重建（會清空資料）。

### 唯一性

- `users.email`、`users.account`：**有值才查重**，各自全站唯一（兩者至少填一個）。
- 名冊條目：`doc id ＝ uid＋學年度＋學期` **由系統組出，天然唯一**，不受輸入欄位影響；
  檔案／表單「找到人」用的辨識鍵＝電子郵件地址或帳號（兩者都填須指向同一帳號）。
- 學號：單筆新增／編輯會檢查同一學期該身分不重複；批次匯入不檢查（重複一律放行，事後自行修改）。

### 孤兒條目與銜接

刪除帳號時名冊條目可保留（處理範圍「所有學期／僅本學期」），保留下的條目其 `uid` 已查無使用者文件——
名冊頁該列顯示**鎖鍊斷開圖示**（滑過顯示「無對應帳號」），即**孤兒列**（歷史學期條目在帳號刪除後同理）。

- **自動銜接**：建立單筆帳號（`POST /api/admin/accounts`）、批次建立／批次修改帳號
  （`POST /api/admin/accounts/batch`）、編輯帳號變更辨識鍵（`PUT /api/admin/accounts`）時，
  以**電子郵件地址＋帳號**兩個鍵找出孤兒條目，整批改掛到新 `uid`
  （改寫 `uid` 欄與 doc id `${uid}_${學年度}_${學期}`），回報筆數 `linked`。
  建立帳號同時選「身分」時**先銜接再寫入本期條目**（本期欄位以新填者為準，其餘學期舊條目一併接回）。
- **手動銜接**：名冊頁孤兒列操作選單的「銜接帳號」→ 查詢目標帳號 → 確認改掛；
  API `POST /api/admin/roster/link`（body `{ uid, key }`，`key`＝目標帳號的電子郵件地址或帳號）。
  查不到帳號時，先至「使用者帳號管理」建立同辨識鍵的帳號（建立當下即自動銜接）。
- 守則：**只接 `uid` 已查無使用者文件的孤兒**（仍活著的帳號一律不動）；
  目標帳號已有該學年度學期同身分條目時**跳過不覆寫**；改掛後回「已銜接 N 筆」。

## 表 6：身分啟用開關（存於 `settings/system`）

不是獨立集合：開關是系統設定文件 `settings/system` 上的 `roleEnabled` 欄位，
回答「四種身分現在是否開放全校登入」。屬**現行狀態、不按學期分文件**，學期轉換自動沿用，
變更歷史另記錄於稽核紀錄（`role_settings_updated`）。

| 欄位 | 鍵名 | 型別 | 說明 |
|---|---|---|---|
| 啟用狀態 | `roleEnabled` | `{ student, parent, staff, admin: boolean }` | 停用＝全校無人可以該身分登入 |

- 欄位不存在或毀損＝四種身分**一律視為啟用**（fail-safe，不影響登入）。
- 讀取走 `settings/system`（`lib/role-settings.ts`，30 秒快取，寫入後失效）；
  系統設定整份覆寫時會保留此欄位，不會被重置。
- 套用時機：登入候選（`detectRoleCandidates`）、選擇／切換身分、以及每請求的
  `dal.verifySession`（停用後既有 session 同步失效）。系統維護模式只保留管理員時不套用此設定。
- 停用「管理員」一律禁止（否則所有管理員失效，無人可再回到本頁啟用）。

## 表 7：學校單位層級（存於 `settings/school`）

不是獨立集合，也不是 `settings/system` 的欄位：單位結構存為**同集合的另一份文件**
`settings/school`（系統設定的 PUT 是整份覆寫，混在 `system` 會被清掉）。
回答「本校有幾個層級、每個單位（處室／組別）在哪一層、上級是誰」，
屬**結構性資料、不按學期**。完整規格（API、驗證、表格與拖曳兩種設定方式）
見 [`docs/學校單位層級設定.md`](./學校單位層級設定.md)。

| 欄位 | 鍵名 | 型別 | 說明 |
|---|---|---|---|
| 層級數 | `levelCount` | `number` | 1～5，由管理人員自訂 |
| 各層名稱 | `levelLabels` | `string[]` | 長度恆等於 `levelCount` |
| 單位 | `units` | `{ code, name, level, parent }[]` | 扁平陣列，`parent`＝上級單位 `code`、最上層為 `null` |

- 屬「學校基本設定」模組（`schoolSettings`，僅超級管理員），
  頁面為子功能入口 `/admin/school-settings` → `/admin/school-settings/org`，
  API 為 `GET/PUT /api/admin/school/org`。
- `code` 為穩定代碼（改名不變），供日後教職員名冊 `unit` 等欄位引用。

## 表 8：校務基本資料（存於 `settings/schoolProfile`）

不是獨立集合，也不是 `settings/system` 或 `settings/school` 的欄位：校務資料存為**同集合的另一份文件**
`settings/schoolProfile`（`settings/system` 與 `settings/school` 的 PUT 都是整份覆寫，混放會被清掉）。
回答「本校有哪些教育階段與學制年數、現任校長與副校長、各校區的地址與電話、學校官網是什麼」，
屬**結構性資料、不按學期**。完整規格（API、驗證、四區介面）見
[`docs/學校校務基本資料.md`](./學校校務基本資料.md)。

| 欄位 | 鍵名 | 型別 | 說明 |
|---|---|---|---|
| 教育階段與年制 | `stages` | `{ stage, years }[]` | `stage` 為固定值（`primary`／`juniorHigh`／`seniorHigh`／`university`），`years` 1～12 |
| 現任校長 | `principal` | `string` | ≤ 40 字，可留空 |
| 現任副校長 | `vicePrincipals` | `string[]` | 0～10 位，姓名不可重複 |
| 校區 | `campuses` | `{ id, name, address, phone }[]` | 1～10 筆；1 筆即單一校區，`id` 為穩定代碼 |
| 學校官網 | `website` | `string` | 可留空；填寫須為 http/https URL |

- 屬「學校基本設定」模組（`schoolSettings`，僅超級管理員），
  頁面為子功能入口 `/admin/school-settings` → `/admin/school-settings/profile`，
  API 為 `GET/PUT /api/admin/school/profile`。

## 表 9：年段班級（存於 `settings/schoolClasses`）

不是獨立集合，也不是 `settings/system`、`settings/school` 或 `settings/schoolProfile` 的欄位：
年段班級存為**同集合的另一份文件** `settings/schoolClasses`（前三者的 PUT 都是整份覆寫，
混放會被清掉）。回答「本校有哪些年段（**一個年段＝一個年級**）、各年級有哪些班級」，
介面依校務基本資料的**學制分區**顯示、學制由年級編號自動推導，
屬**結構性資料、不按學期、全校一份**（不按校區）。完整規格（API、驗證、卡片式介面）見
[`docs/學校年段班級設定.md`](./學校年段班級設定.md)。

| 欄位 | 鍵名 | 型別 | 說明 |
|---|---|---|---|
| 年段（＝年級） | `grades` | `{ id, grade, code, name, classes }[]` | 0～**年制總和** 筆（上限取自校務基本資料，無固定常數）；`id` 為穩定代碼；`grade` **全校唯一**且由小到大，**所屬學制由編號推導**（不另存欄位）；`code` ≤10 字且**全校唯一**；`name` ≤20 字且**同學制內唯一** |
| 班級 | `grades[].classes` | `{ id, code, name, group, department }[]` | `id` 為穩定代碼；`code` ≤20 字且**全校唯一**；`name` ≤40 字且同年級內唯一；每年級 ≤30 班、全校 ≤300 班；**陣列順序＝班級順位**（介面可前後移動，日後顯示全年段班級預設以此排序） |
| 群別／科別 | `classes[].group`／`department` | `{ code, name } \| null` | **僅高級中等學校學制**的班級；`code` ≤20 字、`name` ≤40 字，兩者需同時填寫 |
| 年級名稱預設 | `nameStyle` | `"local" \| "global"` | 學制內序號（1～3 年級）或全域編號（10～12 年級）；只影響之後新增年級的預設名稱，缺省＝`local` |

- 屬「學校基本設定」模組（`schoolSettings`，僅超級管理員），
  頁面為子功能入口 `/admin/school-settings` → `/admin/school-settings/classes`，
  API 為 `GET/PUT /api/admin/school/classes`。
- `id`（`g_`／`cl_` 前綴）為穩定代碼（改名不變），供日後名冊 `grade`／`classCode`／
  `className` 等欄位引用（目前名冊仍為自由文字，尚未串接）。
- **驗證依賴校務基本資料**：API 讀 `settings/schoolProfile` 組成上下文
  `{ stages: { stage, years }[] }`，用來判斷年級編號範圍（依學制順序連續展開）、
  年段數量上限（＝年制總和）與所屬學制；`GET` 一併回傳 `stages` 供前端共用。
  **學制不另存**：由年級編號推導（`stageOfGrade`），班級可否填群別科別也由此決定。
- **舊資料免遷移**：早先的 `segments`（年段包年級）由 `collectRawGrades` 讀入時自動攤平，
  寫回一律為新結構 `grades`。

## 狀態語意

- **狀態只有兩值**：`有效`／`無效`（介面稱「停用」）。舊資料的「停權」讀取時一律當作無效。
- **帳號狀態擋登入**：`users.status ≠ 有效` → 登入直接拒絕（一律回通用錯誤訊息，不透露帳號狀態）。
- **名冊狀態擋身分**：該期該身分 `status ≠ 有效` → 該身分不可選；當期名冊全無效或無條目 → 「當期名冊未建立或皆無效，請聯絡管理員」。

## 登入流程

1. `users` 查 1 筆（`email` 或 `account`）→ 狀態／鎖定／密碼。
2. 2FA（帳號層，登入時驗證一次）。
3. 查當期 4 表中 `uid` 相同且 `status=有效` 的條目 → 候選身分。
   - 0 筆 → 「當期名冊未建立或皆無效，請聯絡管理員」。
   - 1 筆 → 直接進入。
   - 多筆 → `preferredRole` 命中候選則直達，否則 `/choose-role`。
4. `session = { uid, role, entryId, period, candidates[] }`；稱謂與學號班級一律取自名冊條目。
   - `users.mustChangePassword = true` → 登入後立即顯示全螢幕「請先修改密碼」遮罩，
     改完（`/api/auth/change-password`）才放行；遮罩只擋畫面，其餘頁面照常。
5. 切換身分＝換 `role/entryId`（`/api/auth/switch-role`），不重驗 2FA。
6. `dal` 每請求校驗 `users.status` ＋ 當期名冊 `status`；`role=admin` 再取 `attribute`／`modules` 做模組授權。

## 管理端約定

共三個與帳號／名冊相關的功能（前兩個為管理員專屬模組，第三個每人一份）：

- **帳號、身分與安全管理**（個人頁，**不是模組、人人皆有**）：管理自己的姓名／電子郵件／帳號、
  密碼、兩階段驗證、慣用身分。學生／家長／教職員在各自功能首頁的 `／{role}／account`；
  管理員由首頁固定卡片（或「使用者帳號管理」頁的按鈕）進入 `/admin/admins`。
- **使用者帳號管理**（`users` → `/admin/accounts`）：管理員／被授權管理員專屬。
  全部使用者帳號的**單一工作表（無分頁）**：新增／編輯帳號、重設密碼、慣用身分、
  帳號狀態（啟用／停用）、刪除帳號（名冊條目處理範圍可選，見下）。
  - **單筆新增可同時建立身分**：表單下方「同時建立身分」選學生／家長／教職員／管理員，
    即帶出該身分的名冊專屬欄位（`rosterEntryFieldDefs`），建立帳號的同時寫入**當期**
    （目前學年度學期）名冊條目；不選＝只建帳號（事後至「身分名冊管理」指定）。
    API：`POST /api/admin/accounts` 的 `roster: { role, input }`，名冊欄位以
    `validateRosterInput` 驗證、帳號三欄以帳號輸入為準，學號查重用 `loadRosterIndex`。
  - **批次管理**：上傳 Excel／CSV（.xlsx、.xls、.csv，最多 900 列），
    三種模式「新增／修改／刪除」，以**電子郵件地址或帳號**辨識既有資料
    （兩者都填須指向同一帳號）；先「上傳預覽」列出逐列結果，再「確認執行」。
    新增可一併設姓名／密碼／帳號／慣用身分，並可填「**身分**」欄＝同時建立當期該身分
    （需一併填該身分的名冊專屬欄位，標題別名跨四身分合併，如「學號」「屬性」；
    學號查重只與當期**同身分**名冊比對，含本檔前列）；修改僅動姓名、帳號、慣用身分、狀態
    （空白＝不修改），**不支援批次改電子郵件與密碼**；刪除不可復原，名冊條目處理範圍
    （**所有學期／僅本學期／完全保留**）由確認視窗選擇，預設為所有學期。
    預覽與結果的「新增 N 筆」會標示同時建立身分的筆數（`rostered`）。
    刪除後以相同辨識鍵重建帳號，保留的名冊條目會自動銜接回新帳號（`linked`，見「孤兒條目與銜接」）。
    API：`POST /api/admin/accounts/batch`（`mode`＋`dryRun`＋`file`＋`rosterScope`，僅刪除模式使用後者）。
- **身分名冊管理**（`roster` → `/admin/roster`）：管理員／被授權管理員專屬。
  四分頁名冊（學生／家長／教職員／管理員）**含家長**，
  頁頂端為四種身分的啟用／停用（現行開關，存於系統設定；原「身分管理」併入）。
  - 單筆新增一律**綁定既有帳號**（一帳號最多四種身分，同身分同一學期僅一筆）；
    不建立新帳號、不設密碼——建帳號到「使用者帳號管理」。
  - 編輯僅維護名冊欄位；姓名／信箱／帳號（含密碼、慣用身分）唯讀，屬帳號層。
  - **批次管理**：上傳 Excel／CSV（.xlsx、.xls、.csv，最多 900 列），三種模式
    「新增／修改／刪除」，以**電子郵件地址或帳號**辨識該列（兩者都填須指向同一帳號）。
    名冊的唯一鍵＝**uid＋學年度＋學期**（doc id 由系統組出，欄位值不影響唯一性）；
    姓名、學號等其餘欄位重複可寫入；先「上傳預覽」列出逐列結果，再「確認執行」。
    - 新增（寫入方式二選一，預設「追加」）：只在**既有帳號**建立本期名冊條目——
      查無帳號（兩鍵皆無對應）之列略過並回報，不建立帳號、不設密碼；
      **姓名必填**，未填之列略過（不沿用既有帳號姓名）。
      - **追加**：保留同一學期既有條目，在其之上繼續增加，已存在者略過。
      - **覆蓋**：**先刪除同一學期既有的該身分名冊**，再依檔案新增（檔案＝完整名單，
        不在檔案內者本期該身分會消失）；選到覆蓋即顯示警語、預覽列出將刪除的筆數、
        確認鈕改為紅色「確認覆蓋」，確認對話載明刪除筆數與無法復原；
        預覽有任何略過列即禁止執行（避免清空後建不出來）；
        管理員身分保留自己的管理員身分與最後一位有效管理員（檔案包含者仍覆寫重建）。
    - 修改：只更新本期名冊欄位（含姓名）——除**辨識欄位**外全數可留空，
      空白＝不修改，只寫入有填值的欄位；本期無此身分之列略過；
      電子郵件、帳號、密碼不在批次範圍，請至「使用者帳號管理」維護。
    - 刪除：僅刪本期名冊條目，帳號與其他學期保留，不可復原。
    API：`POST /api/admin/roster/batch`（`mode`＋`strategy`＋`dryRun`＋`file`）。
  - 「停用／啟用」＝名冊層狀態（僅本期該身分）；「刪除」＝僅刪本期名冊條目，帳號保留。
  - **孤兒列**（查無對應帳號）在姓名旁顯示鎖鍊斷開圖示（滑過顯示「無對應帳號」），
    操作選單無「編輯」、改提供
    「銜接帳號」（＋停用／刪除）；銜接＝找回帳號後整批改掛，見「孤兒條目與銜接」。
- **兩種狀態分開調**：帳號狀態（擋登入）在「使用者帳號管理」；名冊狀態（擋身分）在「身分名冊管理」。
- 範例檔（`docs/範例_*.xlsx`，由 `/api/admin/downloads/[file]` 提供，依檔名分流權限）：
  使用者帳號管理四份（批次新增／批次新增含身分／批次修改姓名／批次刪除，
  三種模式皆有下載連結，新增模式有兩份）；
  身分名冊管理九份＝學生／教職員／管理員 × 新增／修改／刪除，
  九種組合皆有下載連結，頁面依「目前身分＋模式」吻合時顯示。
  家長由表單建立，不提供 Excel 匯入（`IMPORTABLE_ROLES` 僅 student／staff／admin）。
- 一般管理員未授權模組：API 回 403、首頁卡片隱藏（個人頁卡片不受模組限制；
  「系統設定」為基本入口、卡片一律顯示，其可設定範圍僅超級管理員；
  「學校基本設定」為超級專屬模組，卡片與頁面皆僅超級管理員可用）。

## 舊欄位對照（已清除，僅供追溯）

| 舊 | 新 |
|---|---|
| `students`/`parents`/`staff`/`admins` 四集合 | `users`（帳號）＋ 名冊四表（期別資料） |
| 舊 `roster` 集合（單表含 role） | 名冊四表 |
| `active` | `users.status` |
| `displayName` | `users.name` ／ 名冊 `name` |
| `twoFactorEnabled`、`twoFactorMethod` | `users.twoFactor` |
| 舊 `className`（值 101＝代號） | 名冊 `classCode` 班級代碼 |
| 舊 `classNumber` | 名冊 `rollNo` 班號；`seatNo` 座號留空 |
| 舊 `studentName`（家長） | 重新啟用為家長名冊 `studentName` 學生姓名；另設 `studentEmail` 學生電子郵件地址 |
| 舊帳號上的名冊欄位 | 全數移至名冊四表 |
