## 1. 架構心智模型（5 分鐘）

1. **三角分工**：A `campus-toolkit` 是宿主主程式（學校部署的那支）；B `campus-toolkit-marketplace` 是模組市集（索引＋zip＋checksum）；C 是你自己的模組 repo（一個「外掛」＝一個獨立 git repo，內容就是掛進宿主後的那個資料夾本身）。
1. **沒有微前端**：外掛不是 runtime 載入的套件，而是**審核後複製進宿主 repo 的原始碼**，靠 `next build` 重新部署才生效（`docs/主程式模組與功能模組.md` §2.3）。因此「安裝」永遠伴隨「重部署」，也正因如此宿主的 CSP、路由保護都不必為模組改動。
1. **單向依賴**：模組可以 import 宿主公開面白名單（第 5 章），宿主核心檔**不可** import 你的模組（只有掃描器自動產生的註冊表與轉接檔例外）。開發期宿主核心檔凍結，需要擴充公開面時另開 commit／PR 說明（`docs/主程式模組與功能模組.md` §4-1）。
1. **兩套安裝機制互不相干**：
   1. 本機開發：`module:link` 複製＋監聽（產物已 gitignore，不進 git、不連市集）。
   1. 線上安裝：從市集取回 zip → 十步驗證鏈 → 自動 commit＋push 到**該部署所連結的 fork**（這是 production 的持久化機制）。
1. **啟用 ≠ 安裝**：模組裝進來後預設未啟用（fail-safe 朝關），由超級管理員在 `/admin/modules` 總開關打開；`status` 欄位只是展示資訊。

## 2. 開發環境準備

1. 取得宿主：clone 或 fork `takan003/campus-toolkit`，在該目錄 `npm install`。
1. 環境變數：複製 `.env.example` 為 `.env.local` 並填入 Firebase 與 `SESSION_SECRET`（至少 32 字元）；缺檔時 dev server 仍會起，但登入、Firestore 相關功能會失敗。
1. **先補 `next-env.d.ts`**（常見第一個坑）：全新 clone 沒有此檔（在 `.gitignore`），`npm run lint` 會報 `error TS2307: Cannot find module '../../docs/change.png'`。執行一次 `npx next typegen` 或先跑過 `npm run dev` 即會產生。
1. 起本機伺服器：`npm run dev` → http://localhost:3000。
1. 模組自己的 repo：`git init` 一個獨立 repo，內容只有模組資料夾本身（第 3 章），**不要**把宿主 repo 當你的工作目錄。

## 3. 目錄結構與掛載原理

1. 你的 repo 結構（＝掛進宿主後 `src/modules/<value>/` 的原樣）：

   ```text
   <module-repo>/
   ├── module.json        # manifest：唯一註冊來源
   ├── README.md          # 說明、開發者、版本、安裝後設定方式、資料集合清單
   ├── admin/             # 管理端頁面
   ├── api/               # API route handler
   ├── components/        # 模組專屬元件
   ├── lib/               # 模組專屬伺服器邏輯（server-only）
   ├── types/             # 模組專屬資料模型
   ├── tests/contract/    # 契約測試（`docs/模組市集與外掛開發.md` 附錄 A）
   └── package.json       # 僅 scripts（dependencies 不生效，非空會被拒）
   ```

1. **實體路徑＝`routes` 路徑原樣鏡像**：`{ "kind": "page", "path": "/admin/hello" }` 對應 `admin/hello/page.tsx`；`{ "kind": "api", "path": "/api/admin/hello" }` 對應 `api/admin/hello/route.ts`。掃描器只在實體存在時產生薄轉接檔——可先註冊後實作，實體未出現＝該路徑 404。
1. **沒有獨立的 parent／staff／student 目錄**：其他身分頁面同樣放在 `admin/`、`api/`、`components/` 下，靠 `routes[].path` 掛到 `/student`、`/parent`、`/staff` 前綴、靠 `provides` 決定入口（`docs/模組市集與外掛開發.md` §6.3-10 四前綴白名單）。
1. 掛載後宿主會多出三類東西，**全部不入你的 commit**：`src/modules/<value>/`（複製體）、`module.lock.json`（宿主的安裝清單，屬宿主）、`src/app/**` 薄轉接檔（掃描器生成物）。

## 4. 十分鐘最小模組（Hello）

1. **`module.json`**（把 `helloModule` 換成你自己的 `value`，全域唯一）：

   ```jsonc
   {
     "value": "helloModule",
     "label": "你好模組",
     "kind": "optional",
     "status": "building",            // planned → building → live（上架需 live）
     "description": "範例：示範掛載、權限與主題 token。",
     "href": "/admin/hello",          // ""＝尚未建頁
     "author": { "author": "你的名字", "authorUrl": "", "version": "0.1.0", "releasedAt": "2026-10-22" },
     "provides": { "student": false, "parent": false, "staff": false, "admin": true },

     "routes": [
       { "kind": "page", "path": "/admin/hello" },
       { "kind": "api", "path": "/api/admin/hello" }
     ],
     "permission": { "mode": "new", "value": "helloModule", "category": "校務資料" },
     "icon": "helloModule",           // 非 ModuleIcon 鍵時走 fallback
     "rateLimits": [
       { "key": "HELLO_MODULE_ADMIN", "limit": 60, "windowMs": 60000 }
     ],
     "auditActions": ["hello_module_updated"],
     "dataCollections": ["helloItems"],
     "hooks": [],

     "contractVersion": 1,
     "minHostVersion": "0.558",
     "license": "MIT",
     "repository": "https://github.com/<owner>/<module-repo>"
   }
   ```

   欄位意義與其餘選填（`firestoreIndexes`、`defaultRoleEnabled`、`changelog`、`managerPermissions`）見 `docs/模組市集與外掛開發.md` §3.3。

1. **`admin/hello/layout.tsx`**（管理頁一律包閘門，`moduleKey` 必須等於 `value`）：

   ```tsx
   import AdminSectionShell from "@/components/AdminSectionShell";

   export default function HelloLayout({ children }: { children: React.ReactNode }) {
     return (
       <AdminSectionShell
         moduleKey="helloModule"
         title="你好模組"
         description="範例模組。"
         deniedMessage="「你好模組」未被指派給此帳號，請洽管理員在「功能模組管理」頁指派。"
       >
         {children}
       </AdminSectionShell>
     );
   }
   ```

1. **`admin/hello/page.tsx`**（頁面只用語意 token，禁寫死色票）：

   ```tsx
   "use client";

   export default function HelloPage() {
     return (
       <section className="space-y-3 p-4">
         <h1 className="text-xl text-t1">你好模組</h1>
         <p className="text-t2">這是掛載驗證用的最小頁面。</p>
         <div className="border-themed bg-card p-3">
           <span className="text-t3">卡片區塊</span>
         </div>
       </section>
     );
   }
   ```

1. **`api/admin/hello/route.ts`**（守門三件套，缺一不可）：

   ```ts
   import { NextRequest, NextResponse } from "next/server";
   import { assertSameOrigin } from "@/lib/csrf";
   import { enforceRateLimit, RATE } from "@/lib/rate-limit";
   import { requireAdminModule, toAuthResponse } from "@/lib/dal";

   export async function GET(request: NextRequest) {
     const limited = enforceRateLimit(
       request,
       "hello-module-admin",
       RATE.HELLO_MODULE_ADMIN.limit,
       RATE.HELLO_MODULE_ADMIN.windowMs
     );
     if (limited) return limited;

     const { denial } = await requireAdminModule("helloModule");
     if (denial) return toAuthResponse(denial);

     return NextResponse.json({ ok: true }, { headers: { "Cache-Control": "no-store" } });
   }

   export async function POST(request: NextRequest) {
     const limited = enforceRateLimit(
       request,
       "hello-module-admin-mutate",
       RATE.HELLO_MODULE_ADMIN.limit,
       RATE.HELLO_MODULE_ADMIN.windowMs
     );
     if (limited) return limited;
     if (!(await assertSameOrigin(request))) {
       return NextResponse.json({ success: false, message: "跨來源請求" }, { status: 403 });
     }
     const { denial } = await requireAdminModule("helloModule");
     if (denial) return toAuthResponse(denial);

     return NextResponse.json({ success: true });
   }
   ```

   `RATE` 表已由 `module.json` 的 `rateLimits` 宣告自動合併（`docs/主程式模組與功能模組.md` §3.4-P1），故可直接引用；**不可**手改 `src/lib/rate-limit.ts`。

1. **掛載**（在宿主目錄執行；先停掉 dev server 再掛）：

   ```bash
   npm run module:link -- <你的 repo 路徑> --copy --watch
   ```

   掛完確認 `module.lock.json` 的 `"source"` 是 `link-copy:<路徑>`（若為 `link:` 即掛錯，win32 junction 會全站 Build Error）。之後再 `npm run dev`；`--watch` 視窗必須常駐（改檔 300ms 內同步）。

1. **驗收**：未登入開 `/api/admin/hello` 應回 **401**（不是 Build Error）；dev log 無 `Module not found`／`is invalid` 即掛載成功。完整五項驗證迴圈見第 9 章。

## 6. 權限、CSRF 與限流

1. **API 守門三件套**（每個 route handler 都要做）：`enforceRateLimit`（限流桶）＋ `assertSameOrigin`（CSRF，寫入類請求）＋ `requireRole`／`requireAdminModule`／`requireModulePermission`（鑑權），失敗回 `toAuthResponse(denial)`（401 未登入／403 無權限）。
1. **管理頁閘門**：`layout.tsx` 包 `AdminSectionShell`（`moduleKey` 比對 `session.adminModules`，fail-closed），頁面內不再自行判斷權限。
1. **子權限**：`permission.mode="new"` 會新增一個可指派權限單位；若要在同一模組內分（檢視／審核／匯出…），用 `requireModulePermission("<value>", "<子權限碼>")`，子權限碼在 `module.json` 宣告（如 `managerPermissions`），管理員恆全權。
1. **啟用攔截**：學生／家長等前台 API 建議於鑑權後呼叫 `requireFeatureModuleEnabled("<value>")`——超級管理員 bypass、模組未啟用 fail-safe 擋下；超管 bypass 只在「可見性」層，**不繞過資料寫入驗證**（宿主 §7-3）。
1. **掛勾**：伺服器端到伺服器端的函式呼叫（不走 HTTP、不經限流），故**觸發掛勾的 API 必須自有 `RATE` 桶與守門**；受眾必須明確（`roles`，必要時 `classCodes`），`sourceModule` 必填（`docs/主程式模組與功能模組.md` §6 總則五條）。
1. **路由前綴**：`routes[].path` 只能落在 `/admin`、`/student`、`/parent`、`/staff` 四前綴（這之外沒有 `src/proxy.ts` 角色閘門），且不得與宿主既有路由撞名。
2. **稽核寫入**：`module.json` 宣告的 `auditActions`（前綴＝`value`）會自動合併進 `ActivityAction`（§3.4-P1），變更類 API 應在成功後呼叫 `logActivity({ userId, role, action, ip, details })`（`@/lib/audit`，`ip` 取 `getClientIp(request)`），記錄進全站 `activityLog`、由管理端「活動紀錄」頁統一檢視；函式內部 catch 失敗僅記 console，不會中斷主流程。

## 7. UI 與主題 token 契約

1. **色彩唯一來源＝宿主主題 token**，只有兩種合法寫法（`docs/主程式模組與功能模組.md` §3.5）：
   1. CSS 變數 `var(--…)`，鍵必須屬 `THEME_COLOR_KEYS` 白名單（`src/types/theme.ts`，33 鍵）：`--bg`、`--bg2`、`--t1`、`--t2`、`--t3`、`--bd`、`--bd2`、`--card`、`--sh`、`--primary`、`--primary-hover`、`--primary-text`、`--primary-text-hover`、`--primary-block`、`--danger`、`--success`、`--warning`、`--btn-secondary` 系、`--btn-danger` 系、`--btn-disabled` 系、`--link`、`--link-hover`、`--radius`、`--font-sans`、`--font-mono`、`--transition`。
   1. 宿主主題化工具類別：`.bg-page`／`.bg-card`／`.bg-surface`、`.text-t1`～`.text-t3`、`.text-primary`／`.text-danger`／`.text-success`／`.text-warning`、`.bg-primary`、`.border-themed`、`.btn-theme`／`.btn-soft`／`.btn-primary`／`.btn-danger`、`.input-theme`、`.alert-danger`／`.alert-info`、`.menu-item`、`.animate-fade-in`；`button`／`table`／`input`／`dialog` 等元素級預設已全域主題化。Tailwind **非色彩** utility（間距、版面、字級、圓角）自由使用。
1. **禁清單**（逐項核對）：
   1. 禁寫死色票（`#fff`、`bg-gray-100`、`text-red-500`…）；例外僅兩類——語意色底上的固定對比文字（如 `--danger` 底上 `color:"#fff"`）、中性遮罩 `rgba(0,0,0,…)`。
   1. 禁模組自帶 `.css` 檔。
   1. `var()` 禁寫 fallback（`var(--warning)` 可、`var(--warning,#f59e0b)` 不可——fallback 會掩蓋 token 缺漏）。
   1. 禁寫死寬度（如 `w-[800px]`），一律響應式（`sm:640`／`md:768`／`lg:1024`／`xl:1280`），表格過寬用外層 `overflow-x-auto`。
   1. 禁 `window.confirm`／`window.alert`／`window.prompt`，一律 `role="dialog"`／`role="alertdialog"` ＋ `aria-modal="true"` 的主題化 modal。
   1. 禁 `<button>` ＋「收合/展開」文字或 ▲▼ 字元，一律 `<details>`／`<summary>` ＋ `@/components/DisclosureArrow`。
1. **訊息元件**：宿主側儲存回饋慣例是 `@/components/Toast`；`AGENTS.md` 明文「不適用於 C 選用功能模組」——模組可用自有訊息元件（如 `examRegistration` 的 FlashModal），但上述 token、禁清單、a11y 規範仍全部適用。
1. **省流與分頁**（`AGENTS.md` UI 2/3、`docs/資料讀取省流.md`）：
   1. 閘門：列表預設不載入——`useDataSaver()`（`@/lib/data-saver`）回傳的 `ready` 為 `true` 前不發列表請求，關鍵字搜尋放在閘門外。
   2. 以 `RevealListCard` 取代列表的頁面，須先由 count 端點取得總數顯示在 `summary`（如「目前發布中 N 筆」），不得只放無資訊按鈕。
   3. 分頁：無班級前提（公告、場次）＝每頁筆數＋頁碼導覽；有班級前提（名冊）＝預設按班級代碼切頁。
1. **驗收**：至少切 `builtin:dark` 與 `builtin:highcontrast` 兩主題檢視你的頁面，文字、邊框、按鈕皆須可讀。

## 8. Firestore 讀取與資料層

1. **六鐵律**（`docs/資料庫讀取規範.md` §二，修改任何 Firestore 讀取前必讀）：先問要不要讀、過濾下推、精準查詢、禁 N+1 與分塊（`getAll` 200 筆/批、`in` 30 值/批）、同請求內復用（敏感欄位剝除）、快取＋寫後失效（`cachedRead`／`cachedListRead` ＋ `invalidateReadCache`／`invalidateAdminListCache`）。
1. **交付前**逐項核對該文 §六檢查清單（含清單 TTL 10 分鐘防呆、authz 5–10 秒、禁無界查詢／`onSnapshot`／輪詢）。
1. **`dataCollections` 宣告即承諾**：只准讀寫所列集合＋掛勾集合（`announcements`、`calendarEvents` 自動豁免）；漏宣告而誤用集合字面值會被 `module:check` 掃出（補宣告可排除誤報）。
1. **複合索引**：範圍查詢＋ `array-contains` 等需複合索引的查詢，在 `firestoreIndexes` 宣告（欄位順序＝建索引順序）；漏宣告而踩 `FAILED_PRECONDITION` 屬作者責任。
1. **掛勾寫入**只准走 `publishFromModule`／`updateFromModule`／`publishScheduleFromModule`——校驗與清快取內建，呼叫端不得繞過、不得自開平行集合。

## 9. 驗證與交付

1. **掛入驗證迴圈**（每次改動與同步宿主後跑，5 項全過才算「掛得上、沒壞」，`docs/模組市集與外掛開發.md` §3.4-7）：
   1. `npm run lint`（在**宿主**目錄跑，eslint ＋ tsc）。
   1. `/admin/modules` 出現本模組卡。
   1. 模組頁可開（無權限被擋）。
   1. API 正常、無權限回 403、未登入回 401。
   1. 首頁卡片依設定顯示。
1. **外部 repo 不能獨立 `tsc`**（依賴宿主 tsconfig paths）——型別檢查一律掛進宿主跑；`package.json` 只放 `scripts`，`dependencies` 不生效且非空會被拒。
1. **靜態掃描**：宿主目錄 `npm run module:check`（＝`docs/模組市集與外掛開發.md` §6.3 十條）；投稿前另跑 `npm run module:contract-test`（契約測試，附錄 A 案例）。
1. **同步宿主**：fork 工作流 `git fetch upstream && git merge upstream/main`——只碰自己資料夾＝零 git 衝突，但「不衝突 ≠ 不會壞」，同步後必重跑第 1、2、3 項。
1. **版本號**：模組版本只寫在 `module.json` 的 `author.version` ＋ `changelog[0]` ＋ `README.md` 狀態列，格式 semver `x.y.z`；commit 結尾附「版本號更新至 0.1.x」。
1. **文件寫作**（與宿主 `AGENTS.md` 一致）：條列一律寫 `1.` 由渲染器自動編號、超過一行第二行起縮排 3 空格；說明超過 3 點改 `<details>`（4–5 點加 `open`、6 點以上收合）。
1. **README 必填**：功能說明、開發者、版本、安裝後設定方式、資料集合清單、掛勾需求（市集上架會審）。

## 10. 常見錯誤對照表

| 症狀 | 原因 | 解法 |
|---|---|---|
| `Symlink ... is invalid` ＋ `Module not found` 全站 Build Error | E14：win32 junction 被 Turbopack 判為 project root 外無效 symlink | 改用 `module:link -- <路徑> --copy --watch`，並確認 lock `source` 為 `link-copy:` |
| `npm run lint` 報 `TS2307: Cannot find module '../../docs/change.png'` | 全新 clone 缺 `next-env.d.ts`（在 `.gitignore`） | `npx next typegen` 或先跑一次 `npm run dev` |
| 掛載時 `src/modules/<value> 已存在` | 已掛載狀態重掛 | 先 `npm run module:uninstall -- <value>`，再重掛 |
| 掛載後 `npm run lint` 誤判 `.next/dev/types/validator.ts` 滯留引用 | dev server 運行中執行掛載／解除 | 掛載前停 dev server，掛完再啟動 |
| 頁面 Build Error 出現在**你沒寫的檔** | 薄轉接檔與實體不同步（改了 `routes` 沒重掃） | 重跑掛載指令或 `npm run module:scan`（dev 啟動會自動掃） |
| API 回 500 但無型別錯誤 | 漏守門（限流／CSRF／鑑權）或 `RATE` 欄位未由宣告合併 | 對照第 4 章 route.ts 範例補齊三件套與 `module.json` 宣告 |
| `module:check` 報「集合字面值未宣告」 | 程式碼出現 `dataCollections` 之外的集合名 | 補宣告（誤報）或改為只存取已宣告集合 |
| `module:check` 報「前綴不符」 | `rateLimits.key`／`auditActions` 未帶 `value` 前綴 | 改為 `<VALUE>_…` 形式（如 `HELLO_MODULE_ADMIN`） |
| 主題切深色後頁面對比崩壞、或掃描報 hex | 寫死色票或 `var()` 帶 fallback | 對照第 7 章禁清單逐項清理 |
| 安裝鏈拒裝 | `contractVersion` 或 `minHostVersion` 高於宿主 | 降欄位或請校方升級宿主 |
| 想在自己 repo 直接跑 lint | 外部 repo 無宿主 tsconfig paths | 掛進宿主跑 `npm run lint`（型別檢查以宿主為準） |

## 11. 打包上架市集（B）

1. 模組包＝你的 repo 根目錄全部檔案壓成 zip（`module.json` 在根目錄、無外層資料夾），壓縮後 **≤ 500KB**，不含 `node_modules`、不含宿主路徑檔案、禁新依賴。
1. 五檔同步：`releases/<value>.zip`、`index.json`、`site/index.json`（兩者 `modules[]` 逐位元相同）、`modules/<value>/module.json`（與你的 `module.json` 一致）、`releases/notes.txt`；`checksumSha256` 為 64 碼小寫 hex。
1. 上架閘門：在市集 repo 執行 `node scripts/validate-marketplace-index.mjs`（CI 同款，不通過不得發布）。
1. 慣例 commit：`release: publish <value> vX.Y.Z`，一次動上述 5 檔後 push。
1. **「打包C」鐵律**：完成後分別 push C 與 B，**絕不更動或 push A 宿主**。
1. 細節與 publishing checklist：見 `campus-toolkit-marketplace/模組開發與發布指南.md` 與其 `README.md`。

## 12. 給 AI 協作平台的鐵律摘要

可直接貼進你的 AI 專案指示（對應宿主 `AGENTS.md` 的鐵律）：

1. 三支 repo（宿主 A、市集 B、模組 C）未經指示不修改、不 push；「打包C」絕不碰 A；「修改A」後不可把本機掛載的模組 push 上去。
1. 掛載只用 `npm run module:link -- <C 路徑> --copy --watch`；掛載／解除前停 dev server；驗 `module.lock.json` 的 `source` 為 `link-copy:`。
1. 只 import 第 5 章白名單；禁手改註冊表／`RATE`／`ActivityAction`／`ICON_PATHS`、禁 `settings/system`、禁平行公告與行事曆集合。
1. API 必做守門三件套；管理頁必包 `AdminSectionShell`；路由只用 `/admin`／`/student`／`/parent`／`/staff` 四前綴。
1. 色彩只用主題 token 與語意工具類別；禁寫死色票、禁自帶 CSS、`var()` 禁 fallback、禁寫死寬度、禁 `window.alert/confirm/prompt`、收合用 `<details>` ＋ `DisclosureArrow`。
1. 讀 Firestore 前先讀 `docs/資料庫讀取規範.md`，依六鐵律與文末檢查清單逐項核對。
1. 交付順序固定：`npm run lint`（宿主）→ 版本號（`author.version`＋`changelog`＋README）→ commit 結尾附「版本號更新至 0.1.x」→ 依指示 push。
1. 動 Next.js 程式碼前先讀 `node_modules/next/dist/docs/`（宿主 Next 版本可能與你的認知不同）。
1. 說明文字格式：條列一律 `1.` 自動編號、超過一行第二行縮排 3 空格；超過 3 點用 `<details>`（4–5 點 `open`、6 點以上收合）。
