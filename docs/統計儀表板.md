# 統計儀表板（stats）

管理端的超級專屬權限模組 `stats`（`scope: superOnly`）與其頁面 `/admin/stats`：
彙整目前專案在 **App Hosting（Cloud Run／Cloud Build）** 與 **Firebase（Firestore）** 的使用量，
對照免費額度並顯示近期趨勢，供超級管理員判讀「額度快用完了沒」
（Firestore 讀取曾單日衝至 4.2 萬次逼近 5 萬免費額度）。

- **入口**：管理員首頁 →「統計儀表板」卡片 → `/admin/stats`
  （版頭、權限閘門與頁尾由共用 `admin/stats/layout.tsx` 提供，
  閘門為 `adminModules.includes("stats")`，fail-closed：讀不到權限＝權限不足）。
- **只讀、不落庫**：用量資料不寫入 Firestore（避免加重讀取量），
  由伺服器端 5 分鐘記憶體快取後回給前端；未設定環境變數時回「設定指引」而非錯誤。
- **金鑰不外流**：服務帳號只在伺服器端使用，CSP 不需因本頁調整。

## 名詞

| 名詞 | 說明 |
|---|---|
| 免費額度 | App Hosting 相關產品（Cloud Run／Cloud Build）的每月內含量；Firestore 的每日內含量（太平洋時間午夜重置） |
| 計費週期 | App Hosting 用量以「本月 1 日 ~ 目前（UTC）」區間查詢，每月重置 |
| 太平洋日曆日 | Firestore 額度重置時區（`America/Los_Angeles`）的日曆日，程式以 `startOfPacificDay()` 切日 |
| App Hosting 組成 | 靜態走 Cloud CDN、SSR 走 Cloud Run、部署建置走 Cloud Build；本頁取後兩者的計費關鍵指標 |

## 額度表（常數）

App Hosting（`src/lib/usage-apphosting.ts` 的 `APP_HOSTING_FREE_LIMITS`，每月，UTC）：

| 資源 | 免費額度 | 指標 |
|---|---|---|
| Cloud Run 請求數 | 2,000,000 次 | `run.googleapis.com/request_count` |
| Cloud Run CPU 時間 | 180,000 vCPU-秒（頁面顯示 50 小時） | `run.googleapis.com/container/cpu/allocation_time` |
| Cloud Run 記憶體時間 | 360,000 GiB-秒（頁面顯示 100 GB-hrs） | `run.googleapis.com/container/memory/allocation_time` |
| Cloud Build 建置次數 | 無次數額度（`limit=null`；免費額度以「建置分鐘」計 2,500 分鐘／月） | `cloudbuild.googleapis.com/build/count` |

Firestore（`src/lib/usage-firebase.ts` 的 `FIRESTORE_FREE_LIMITS`，每日）：

| 資源 | 免費額度 |
|---|---|
| 文件讀取 | 50,000 |
| 文件寫入 | 20,000 |
| 文件刪除 | 20,000 |

## 資料模型

**不寫 Firestore**，僅 API 回應型別（`src/types/usage.ts`，不含 `server-only`，前後端共用）：

```ts
interface QuotaMetric { key: string; label: string; used: number; limit: number | null; unit: QuotaUnit }
type QuotaUnit = "count" | "hours" | "gbHours";
interface UsageSection { ok: boolean; configured: boolean; message: string | null; hint: string | null; fetchedAt: string; note?: string | null; links?: UsageLink[] }
interface AppHostingUsage extends UsageSection { period: { from: string; to: string }; metrics: QuotaMetric[] }
interface FirebaseUsage extends UsageSection { today: {reads;writes;deletes}; limits: {...}; daily: FirestoreDayUsage[] }
interface StatsResponse { success: boolean; appHosting: AppHostingUsage; firebase: FirebaseUsage }
```

- `configured=false`：環境變數未設定（顯示設定指引卡）；`configured=true` 且 `ok=false`：已設定但抓取失敗。
- `links`：未設定／失敗時帶**官方用量頁連結**（Firebase App Hosting、Cloud Run、帳單；Firebase Firestore 用量、用量與帳單；GCP 專案 Firestore 用量），前端以可點連結顯示，讓管理人員直接到官方頁面核對額度。
- `limit=null`：該項目無免費額度或單位無法換算，前端顯示「額度未知」。
- `daily` 由舊到新含今日，日期字串為太平洋日曆日。

## API

`src/app/api/admin/stats/route.ts`

| 方法 | 行為 |
|---|---|
| `GET` | 回 `StatsResponse`；兩個來源以 `Promise.all` 各自抓取、互不阻斷，`Cache-Control: no-store` |

- 守門：`requireAdminModule("stats")` —— `adminModulesOf` 對非超級一律剝除該模組，
  因此等同「僅超級管理員」，與頁面層判斷同一把尺。
- 限流：`RATE.ADMIN_USAGE_GET`（30 次/分）。
- 快取：`usage-apphosting`／`usage-firebase` 各自 5 分鐘記憶體快取（失敗結果只快取 30 秒），
  外部 API 每次實際呼叫至多 2 個。

## 資料來源與環境變數

| 來源 | 方式 | 環境變數 |
|---|---|---|
| App Hosting | Cloud Monitoring `projects.timeSeries.list`：Cloud Run 三個指標（`resource.type="cloud_run_revision"`）＋ Cloud Build 建置次數（`resource.type="build"`），皆以日對齊（`alignmentPeriod=86400s`＋`ALIGN_SUM`＋`REDUCE_SUM`）抓回後由程式累加本月合計 | `FIREBASE_SERVICE_ACCOUNT_KEY`（需 `roles/monitoring.viewer`，缺權限時頁面顯示 gcloud 授予指令） |
| Firebase | Cloud Monitoring `projects.timeSeries.list`：`firestore.googleapis.com/document/{read,write,delete}_count`，`alignmentPeriod=3600s`＋`ALIGN_SUM`＋`crossSeriesReducer=REDUCE_SUM`（時期須為 Google Duration 字串、reducer 為 `REDUCE_*`，寫錯會回 400），程式依太平洋時間切日 | 同上（共用同一服務帳號） |

- 共用元件：`src/lib/google-monitoring.ts`（服務帳號解析、權杖快取 45 分鐘、
  `fetchTimeSeries` 呼叫與錯誤解析、缺權限／API 未啟用的授權指引）。

## 頁面

`src/app/admin/stats/page.tsx`（client）

- 工具列：資料更新時間＋「重新整理」鈕。
- App Hosting 區塊：本月請求數／CPU 時間／記憶體時間／建置次數，每資源一張「已用／額度」進度條（≥80% 警示色、≥100% 危險色）；未設定或失敗時改顯示 `NoticeBox`（含設定指引與官方用量頁連結）。
- Firestore 區塊：今日讀／寫／刪三張進度條；未設定或失敗時同樣顯示 `NoticeBox`。
- 趨勢區塊：近 7 日讀／寫群組長條圖，**純 SVG**（不引入圖表函式庫）。
