# 模組沙箱設計（P1-9 第二階段）

> 狀態：設計與 POC 完成（A `0.693`）<br>
> 範圍：選用功能模組的 API、頁面與掛勾執行隔離<br>
> 目標：讓外部模組即使有惡意程式碼，也拿不到宿主密鑰、讀不到任意檔案、不能任意執行系統指令

## 一、為什麼要做

目前模組與主程式在同一個 Node process 執行：

- 模組可以讀 `process.env`（包含 `SESSION_SECRET`、服務帳號金鑰）
- 模組可以 import `node:fs`、`node:child_process` 等內建模組
- 模組可以對任意網域發請求
- 模組與宿主共用同一個 Firestore Admin 權限

P0／P1 已經補上簽章、掃描、`scopedDb`、API 守門與 lock-only 安裝，但那些是「降低風險」，不是「隔離執行」。

## 二、威脅模型

<details open>
<summary>要保護的資產與攻擊面</summary>

1. **宿主密鑰**：`SESSION_SECRET`、`FIREBASE_SERVICE_ACCOUNT_KEY`、GitHub token、SMTP 密碼、`TOTP_ENCRYPTION_KEY`、`UPSTASH_REDIS_REST_TOKEN`。
2. **核心個資**：`users`、名冊四表、學生個人資料三表。
3. **宿主檔案系統**：`.env.local`、`module.lock.json`、部署憑證。
4. **對外網路**：模組不應能任意外傳資料或打內網。
5. **宿主程序**：模組不應能執行系統指令、載入原生 addon、逃出隔離。
6. **可用性**：模組不應能拖垮整個 process（CPU／記憶體／無限迴圈）。

</details>

## 三、可選方案

| 方案 | 隔離強度 | 效能 | 改造成本 | 結論 |
|---|---|---|---|---|
| 同 process＋掃描 | 低 | 最好 | 低 | 目前狀態，不足 |
| Worker thread | 中 | 好 | 高 | 可做，但權限模型是 process-wide |
| **子程序＋Node permission model** | 中高 | 可接受 | 中高 | **建議先做** |
| 獨立的模組服務／容器 | 高 | 視網路 | 很高 | 長期選項 |
| V8 isolate（`isolated-vm`） | 高 | 好 | 很高 | 與 Next／React 不相容，暫不採用 |

### 為什麼選子程序

Node 22 的 `--permission` 可以：

- 預設拒絕檔案讀寫，只允許指定路徑
- 預設拒絕 `child_process`、worker、原生 addon
- 讓子程序只拿到 filtered env

POC 已驗證：子程序看不到 `SESSION_SECRET`、讀不到專案檔案、不能執行 `whoami`，但可以透過 IPC 呼叫模組 handler。

## 四、目標架構

```text
Next.js route handler（宿主）
  │
  ├─ 驗 session／角色／module gate（宿主）
  ├─ 建立 capability token（短效、只含 uid／role／module）
  │
  ├─ IPC ──► 模組子程序（permission model＋filtered env）
  │            ├─ 載入模組 handler
  │            ├─ 需要 session／Firestore 時，透過 RPC 回宿主
  │            └─ 回傳序列化 Response
  │
  └─ 宿主把 Response 回給瀏覽器
```

### 4.1 子程序生命週期

1. 每個模組一個長期子程序（或小型 pool），閒置逾時回收。
2. 子程序啟動時只帶：
   - `MODULE_VALUE`
   - `MODULE_SECRET_<NAME>`（由 `moduleSecret()` 派生）
   - 必要的 `NODE_ENV`、`PATH`
3. 子程序不帶任何宿主密鑰。
4. 子程序 crash 時，宿主回 503，不影響其他模組。

### 4.2 Capability RPC

模組不能直接碰 Firestore／session；改由宿主提供窄介面：

1. `session.get()`：回傳已驗證的 uid／role／account（不含 token）。
2. `db.collection(name).…`：只允許 manifest 宣告的集合，核心集合唯讀。
3. `hooks.publishAnnouncement()`／`publishCalendar()`：與現有掛勾一致。
4. `secret.get(name)`：回傳 `moduleSecret(moduleValue, name)`，不回傳根金鑰。

RPC 訊息必須有大小上限、逾時與次數限制；子程序不能指定 `moduleValue`。

### 4.3 網路

Node permission model **不擋網路**。正式版需要：

1. 在子程序 bootstrap 覆寫 `fetch`、`http`、`https`、`net`、`tls`，預設拒絕。
2. 若模組 manifest 宣告外部網域，宿主在 RPC 層代理請求，只允許宣告的 host。
3. 或者把子程序放進沒有對外網路的容器／network namespace。

### 4.4 頁面

模組 page／layout 是 React server component，不能直接搬到子程序。短期做法：

1. 頁面留在宿主 process，但已在 module context 內執行，`getAdminDb()` 會套 `scopedDb`。
2. 頁面若需要敏感資料，必須走模組 API；API 已在子程序隔離。
3. 長期若要連頁面一起隔離，需要把 page 渲染拆成獨立 renderer，成本更高。

## 五、POC 已驗證

`npm run sandbox:poc` 會：

1. 建立暫存子程序與 handler。
2. 用 `--permission --allow-fs-read=<temp>` 啟動。
3. 只傳 `MODULE_SECRET`，不傳 `SESSION_SECRET`。
4. 驗證：
   - 子程序看不到 `SESSION_SECRET`
   - 讀 `package.json` 被拒絕
   - `child_process` 被拒絕
   - 透過 IPC 呼叫 handler 成功

`npm run sandbox:rpc-poc` 進一步驗證 capability RPC：

1. 子程序 handler 向宿主請求 `session`、模組密鑰與 `db.query`。
2. 宿主只回傳允許的 session／密鑰／集合資料。
3. 子程序仍受 permission model 限制，看不到宿主密鑰。

`npm run sandbox:db-poc` 驗證資料窗口：

1. 模組只能組 `collection／where／orderBy／limit` 查詢。
2. 宿主執行查詢後只回傳符合條件的資料。
3. 宿主保留集合（如 `users`）一律拒絕。
4. 模組拿不到 Firestore credential，也看不到其他集合。

`npm run sandbox:compile-poc` 驗證 import 改寫：

1. 用 SWC 把模組 TS 轉成 ESM。
2. 把 `next/server`、`@/lib/dal`、`@/lib/firebase-admin` 換成沙箱 shim。
3. 子程序在 `--permission` 下執行，handler 不用改寫就能取得 session／查詢資料。
4. 尚未處理多層相對 import、其他宿主模組與 npm 依賴。

`npm run sandbox:f-pilot` 用 **F 真正的程式碼** 驗證：

1. 遞迴編譯 `examRegistration/api/admin/exam-registration/route.ts`、`lib/exam-registration.ts`、`types/exam-registration.ts`。
2. 自動把宿主 import 換成 shim，並提供 `scopedDb` 查詢／寫入代理。
3. F 的 `GET ?summary=count` 回傳正確總數。
4. F 的 `GET` 場次列表回傳正確資料，且依 `examDate` 由新到舊。
5. F 的 `POST` 建立場次、`PATCH` 更新場次、`DELETE` 刪除場次都在 `--permission` 子程序完成。
6. 批次窗口：刪除場次時，連同該場次的報名資料一起批次刪除。
7. 掛勾窗口：建立「開放報名」場次時，透過 window RPC 發公告與寫行事曆。
8. 匯出窗口：CSV 匯出包含名冊學生；XLSX 匯出產生合法的 zip 檔（使用真正的 `xlsx` 套件）。
9. 名冊／統計窗口：班級分頁、班級名冊、stats 統計在子程序完成。
10. 學生端窗口：可見場次查詢、登錄（transaction）、封存、取消在子程序完成。
11. official XLSX：需要身分證字號的官方報名檔，透過 `getAll` 與個人身分窗口產生。
12. 只讀 F 原始碼，沒有修改 F。

F 的功能面到此已完整覆蓋；尚未包含：正式 Next.js 執行路徑整合、子程序 pool／逾時、網路限制、E／G 遷移。

## 六、模組專屬密鑰

新增 `src/lib/module-secret.ts`：

```ts
moduleSecret("selfDirectedLearning", "canva")
```

- 以 HKDF 從 `MODULE_SECRET_ROOT`（建議）或 `SESSION_SECRET` 派生
- 同一模組×用途穩定，不同模組／用途不同
- 模組不需要再讀 `SESSION_SECRET`

E 的 Canva 目前直接使用 `process.env.SESSION_SECRET`；第二階段遷移時改成 `moduleSecret("selfDirectedLearning", "canva")` 即可（需要「修改E」指令）。

## 六之一、建置步驟（Phase 2C）

1. 執行 `npm run module:sandbox-build -- --module examRegistration`，或設定 `MODULE_SANDBOX_MODULES=examRegistration` 讓 `prebuild`／`prelint`／`predev` 自動執行。
2. 產物在 `.module-sandbox/<value>/`：編譯後的 API route、`__sandbox/*.mjs` shim、`manifest.json`。此目錄已 gitignore。
3. 未設定模組時腳本 no-op，不影響上游或未啟用沙箱的 fork。
4. `next.config.ts` 的 `outputFileTracingIncludes` 會把 `.module-sandbox/**/*` 納入 `/api/**` 的 serverless tracing。

## 六之二、Runtime manager（Phase 2C）

1. `withModuleSandbox(moduleValue, routePath, original)` 由 `build-module-registry.mjs` 自動包在每個 API 轉接檔上。
2. `MODULE_SANDBOX_MODULES` 有列出且 `.module-sandbox/<value>/manifest.json` 存在時，請求會送進受限子程序；否則原樣呼叫原 handler。
3. 子程序只拿到**該模組允許的環境變數**（例如只有 E 會拿到 `CANVA_*`）、`MODULE_SANDBOX_ROUTE`、`SANDBOX_CLIENT_IP`；沒有 `SESSION_SECRET`。
4. 子程序需要的 session／Firestore／掛勾，全部透過 host RPC 回主程序執行；`scopedDb` 仍套用模組集合限制。
5. multipart／formData 會由宿主解析後以「文字欄位＋base64 檔案」送進子程序，再重建 `FormData`；不再回退原流程。`npm run module:sandbox-multipart-test` 已驗證。
6. `npm run module:sandbox-wrapper-test` 會用 F 的正式 bundle＋正式 adapter＋假 session／假 RPC 驗證請求與回應；真實 Firestore 端到端測試需要部署環境憑證（本機目前沒有 ADC／emulator）。
7. 網路窗口：子程序的 `fetch` 會改走 host RPC；宿主只允許 `MODULE_SANDBOX_ALLOWED_HOSTS` 內的目的地，拒絕 http、內網位址與重新導向。`npm run module:sandbox-network-test`／`sandbox-fetch-test` 已驗證。
8. 過渡期相容：子程序環境的 `SESSION_SECRET` 是 `moduleSecret(moduleValue, "session")`，不是宿主真正用來簽 session 的值；仍讀 `process.env.SESSION_SECRET` 的模組（如 E 的 Canva）可先運作，之後再遷移 `moduleSecret()`。
9. E pilot：`module:sandbox-e-test`（admin GET）、`module:sandbox-e-student-test`（學生 GET）、`module:sandbox-e-write-test`（儲存草稿）、`module:sandbox-e-submit-test`（送審 transaction＋鎖定文件）、`module:sandbox-e-canva-test`（Canva 設定檢查、授權網址、加密 cookie 回傳與讀取）、`module:sandbox-e-parent-export-test`（家長端讀取、Word DOCX 二進位匯出）、`module:sandbox-e-staff-test`（教職員審核佇列、通過 transaction）已用 E 真正的 route 在 permission 子程序跑通。E 的實際 Canva 回呼／匯出（需外網）與 Google Docs 上傳（需 Google 授權）尚未測。
10. G pilot：`module:sandbox-g-student-test`（學生讀取、儲存草稿、送出確認）、`module:sandbox-g-admin-test`（管理端名冊、統計、CSV、儲存設定）、`module:sandbox-g-parent-staff-test`（家長遮蔽讀取、教職員名冊與財稅查調更新）已用 G 真正的 route 在 permission 子程序跑通；G 沒有外部網路服務，本機流程已全數覆蓋。
11. 資源上限：單一請求逾時 15 秒；同一模組同時最多 4 個子程序；回應超過 32MB 直接中止。`npm run module:sandbox-limits-test` 已驗證同時請求上限與名額釋放。

## 七、分階段計畫

<summary>Phase 2A／2B／2C</summary>

1. **Phase 2A（本次完成）**：威脅模型、`moduleSecret()`、子程序 permission POC、能力掃描。
2. **Phase 2B**：模組專屬密鑰 API＋遷移 E 的 Canva；把模組 handler 包成可序列化的 RPC 介面；資料窗口（query proxy）與透明 import 改寫（`@/lib/firebase-admin`、`@/lib/dal`、掛勾 → sandbox bridge）。

4. **Phase 2D（選配）**：頁面 renderer 隔離、獨立容器／服務。

</details>

## 八、殘餘風險

1. 子程序仍是同一個 OS 使用者；不是 VM／容器等級隔離。
2. Node permission model 不擋網路；必須另外覆寫或放到無網路環境。
3. 子程序可以消耗 CPU／記憶體；需要 timeout、memory limit 與重啟策略。
4. 頁面仍在宿主 process；頁面層的惡意程式碼只能靠掃描與 `scopedDb` 降低風險。
5. 共用子程序 pool 時，模組之間可能透過暫存檔或 IPC 互相影響；需要每次請求清理或一模块一程序。

## 九、非目標

1. 不承諾「未審核模組可以安全 direct production」；沙箱完成前，production 仍只允許官方／已審核模組。
2. 不把 Next.js／React 放進 V8 isolate；頁面與 API 的隔離策略不同。
3. 不在此階段處理跨學校的遠端模組服務。
