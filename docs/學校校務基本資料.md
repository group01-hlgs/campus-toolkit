# 學校校務基本資料（校務基本資料）

「學校基本設定」`schoolSettings`（僅超級管理員）底下的子功能，
子功能代碼 `schoolSettings.profile`。
登記學校最基礎的對外資料：教育階段與學校年制、現任校長、現任副校長（可多位）、
各校區資料（地址、電話，單一或多校區）、學校官網。

- **入口**：管理員首頁 →「學校基本設定」卡片 → 子功能入口卡片「校務基本資料」
  → `/admin/school-settings/profile`。
  「學校基本設定」頁（`/admin/school-settings`）本身是**子功能入口卡片牆**，
  版頭、權限閘門與頁尾由共用 `school-settings/layout.tsx` 提供，新增子功能＝加一張卡片＋一個子路由。
- **結構性資料、不按學期**：學期轉換不會影響，與 `roleEnabled` 同屬現行狀態。
- **供日後引用**：首頁抬頭、對外頁面、表單預設值等皆可從此讀取（目前尚無其他取用點）。

## 名詞

| 名詞 | 說明 |
|---|---|
| 教育階段 | 固定選單：國民小學／國民中學／高級中等學校／大專院校（可複選） |
| 學校年制 | 該教育階段的修業年數，如國民小學 6 年制、高級中等學校 3 年制 |
| 校區 | 一組「名稱＋地址＋電話」；填 1 筆即單一校區、多筆即多校區 |

## 資料模型

存於 **`settings/schoolProfile`**（與 `settings/system`、`settings/school` 同集合的獨立文件）。

- 刻意不放 `settings/system`：系統設定的 PUT 是整份覆寫（只保留 `roleEnabled`），
  混放會在下次儲存系統設定時被清掉。
- 刻意不放 `settings/school`：單位層級設定的 PUT 同樣是整份 `set()` 覆寫，
  兩者放同一文件會互相清掉，因此各佔一份文件。

```ts
interface StageSetting { stage: StageValue; years: number }   // 教育階段＋年制
interface Campus {
  id: string;        // 穩定代碼：新增時產生、改名不變
  name: string;      // 校區名稱（如「本部」），≤ 30 字、不可重複
  address: string;   // 學校地址，≤ 120 字、不可空白
  phone: string;     // 學校電話，≤ 30 字（可留空）
}
interface SchoolProfile {
  stages: StageSetting[];      // 未勾選的階段不出現在陣列；每階段至多 1 筆
  principal: string;           // 現任校長，≤ 40 字（可留空）
  vicePrincipals: string[];    // 現任副校長，0～10 位、姓名不可重複
  campuses: Campus[];          // 1～10 筆；1 筆即單一校區
  website: string;             // 學校官網，≤ 200 字（可留空，須為 http/https URL）
}
```

- 常數與型別：`src/types/school-profile.ts`（**不含 `server-only`**，前端與 API 共用驗證）。
- 空庫＝`{ stages: [], principal: "", vicePrincipals: [], campuses: [1 筆「本部」], website: "" }`。
- 勾選教育階段時的預設年制：國小 6、國中 3、高中 3、大專 4（`defaultYearsFor()`）。

## API

`src/app/api/admin/school/profile/route.ts`

| 方法 | 行為 |
|---|---|
| `GET` | 讀回資料；`readSchoolProfile()` 寬容修正型別與範圍，毀損不整份作廢 |
| `PUT` | body `{ profile }`，整份覆寫 `settings/schoolProfile`；驗證不過回 400 且不寫入 |

- 守門：`requireAdminModule("schoolSettings")` —— `adminModulesOf` 對非超級一律剝除
  該模組，因此等同「僅超級管理員」，與頁面層判斷同一把尺。
- 其他：`assertSameOrigin`、限流 `SCHOOL_PROFILE_GET`（60/分）／`SCHOOL_PROFILE_MUTATE`（20/分）、
  稽核 `logActivity("school_profile_updated")`（details 記教育階段數與校區數）、`Cache-Control: no-store`。

## 伺服器驗證規則

`validateSchoolProfile()`（API 與表單共用，任一不過即 400）：

1. `stages`：`stage` 必須是已知教育階段、不可重複；`years` 為 1～12 的整數。
2. `principal` ≤ 40 字（可空白）。
3. `vicePrincipals` ≤ 10 位；每位非空 ≤ 40 字、姓名不可重複。
4. `campuses` 1～10 筆；`id` 非空且全域唯一；`name` 非空 ≤ 30 字且不可重複；
   `address` 非空 ≤ 120 字；`phone` ≤ 30 字且僅限數字與 `+ - ( ) # 轉 .` 等字元。
5. `website` 可空白；填寫時須能解析為 URL 且協定為 `http://` 或 `https://`，≤ 200 字。

## 介面

`src/components/SchoolProfileEditor.tsx`，沿用單位層級設定的 **saved／draft** 模式：
頂部為**還原**（放棄未存變更）與**儲存變更**（未變更或驗證不過時停用），
驗證訊息即時顯示、未存變更以文字提示。內容分四區：

1. **教育階段與學校年制**：四個教育階段核取方塊；勾選後在該列右側出現「年制」數字輸入（1～12），
   取消勾選即移除該階段。
2. **現任校長與副校長**：校長文字欄（≤ 40 字）；副校長以「新增副校長」逐列加入，
   每列可單獨編輯與移除，人數計數顯示 `n / 10`。
3. **校區資料**：每校區一張卡片（校區名稱、學校地址、學校電話），
   「新增校區」最多 10 筆、「刪除校區」在僅剩 1 筆時停用。
4. **學校官網**：網址欄，可留空。

## 與其他功能的關係

- **不與單位層級混放**：`settings/schoolProfile` 與 `settings/school` 各自獨立文件，
  其中任一方的整份覆寫都不會清掉另一方。
- **不變項**：超級屬性的層級守門、`schoolSettings` 超級專屬、
  `settings/system` 的覆寫行為，皆不因本功能改變。
- **尚無取用點**：欄位目前僅供登錄與後續功能引用（例如頁首學校名稱仍取自系統設定的
  `schoolFullName`，不會因本頁變動）。

## 驗收清單

1. 一般管理員看不到「學校基本設定」首頁卡片；直開 `/admin/school-settings/profile`
   顯示「權限不足」；`GET/PUT /api/admin/school/profile` 回 403。
2. 勾選「國民小學」→ 出現年制欄（預設 6），改為 3 → 儲存後重新整理仍在。
3. 新增第二位副校長、刪除其中一位 → 儲存後結果一致；姓名重複時驗證訊息擋下儲存。
4. 「新增校區」加到 10 筆後按鈕停用；校區名稱重複或地址空白 → 驗證訊息擋下儲存。
5. 僅剩 1 個校區時「刪除校區」停用（至少保留單一校區資料）。
6. 官網填 `www.school.edu.tw`（缺協定）→ 驗證訊息擋下儲存；填 `https://...` 可存。
7. 「儲存變更」後稽核紀錄出現 `school_profile_updated`。
8. **存一次「系統設定」或「單位層級設定」不會清掉校務基本資料**（不同文件）。
