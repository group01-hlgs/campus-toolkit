# 樓層空間設定（樓層空間設定）

「學校基本設定」`schoolSettings`（僅超級管理員）底下的第五個子功能，
暫定子功能代碼 `schoolSettings.spaces`。
管理人員自行決定空間層級數與每層名稱（如「校區 → 大樓 → 樓層 → 空間」），
並設定每個空間的中英文名稱、隸屬單位、隸屬層級、是否開放借用、容納人數與設備說明。
為日後「學校空間預約模組」（`spaceBooking`，規劃中）與行事曆地點欄位準備結構化資料。

- **入口**：管理員首頁 →「學校基本設定」卡片 → 子功能入口卡片「樓層空間設定」
  → `/admin/school-settings/spaces`。
  版頭、權限閘門與頁尾由共用 `school-settings/layout.tsx` 提供。
- **結構性資料、不按學期**：學期轉換不會影響。
- **與單位層級設定同構**：層級樹的規則（層級數、層名、父子關係、整棵子樹搬移）
  與 `學校單位層級設定.md` 一致，差別在空間條目多了中英文名稱、隸屬單位、
  開放借用、容納人數與設備說明等屬性欄位。

## 名詞

| 名詞 | 說明 |
|---|---|
| 空間層級數 | 本校空間分類有幾層（1～6），例如「樓層 → 空間」＝2 層 |
| 層級名稱 | 每一層的稱呼，如「樓層」「空間」；預設即此兩層 |
| 空間 | 一個節點（校區、大樓、樓層、教室、場地…皆是） |
| 上級空間 | 該空間的直接上層；最上層空間沒有上級（＝隸屬空間層級的父層） |
| 隸屬單位 | 該空間管轄的校內單位，選自單位層級設定（`settings/school`）的單位清單 |
| 開放借用 | 該空間是否可被預約等模組借用（預設開啟） |

## 資料模型

存於 **`settings/spaces`**（與 `settings/system` 同集合的獨立文件）。
刻意不放 `settings/system`：系統設定的 PUT 是整份覆寫，混放會在下次儲存系統設定時被清掉。

```ts
interface SpaceUnit {
  code: string;            // 穩定代碼：新增時產生、改名不變（供預約單、行事曆地點引用）
  name: string;            // 中文名稱（同上級內唯一，≤ 40 字）
  nameEn: string;          // 英文名稱（可空白，≤ 60 字）
  spaceCode: string;       // 空間代碼（展示用，如「R-301」；可空白，填寫時全校唯一，≤ 20 字）
  floor: string;           // 樓層（如「3F」「B2」；可空白，≤ 20 字）
  level: number;           // 1..levelCount（＝隸屬空間層級）
  parent: string | null;   // 上級空間 code；最上層必為 null
  orgUnit: string | null;  // 隸屬單位 code（settings/school 的單位）；null＝未指定
  openForBooking: boolean; // 是否開放借用（預設 true）
  capacity: number | null; // 容納人數（0..999 的整數）；null＝未填寫
  notes: string;           // 空間設備說明（可空白，≤ 200 字）
}
interface SpaceStructure {
  levelCount: number;       // 1..6
  levelLabels: string[];    // 長度恆等於 levelCount（≤ 20 字）
  units: SpaceUnit[];       // 扁平陣列，兄弟順序＝陣列相對順序，上限 500 筆
}
```

- 常數與型別：`src/types/school-spaces.ts`（**不含 `server-only`**，前端與 API 共用驗證）。
- 空庫＝`{ levelCount: 2, levelLabels: ["樓層", "空間"], units: [] }`。
- `orgUnit` 引用單位層級設定的單位 code（快照式引用：日後單位改名不追溯、
  刪除單位不會連動刪除空間，API 儲存時只核對「存在」）。

## API

`src/app/api/admin/school/spaces/route.ts`

| 方法 | 行為 |
|---|---|
| `GET` | 讀回設定與單位選項；`readSpaceStructure()` 寬容修正型別與範圍，毀損不整份作廢；一併回傳 `orgUnits`（單位層級設定的 `code`／`name`／`level`／`parent`，供「隸屬單位」下拉分組顯示） |
| `PUT` | body `{ setting }`，整份覆寫 `settings/spaces`；驗證不過回 400 且不寫入 |

- 守門：`requireAdminModule("schoolSettings")` —— 等同「僅超級管理員」，與頁面層判斷同一把尺。
- 驗證依賴單位層級設定：PUT 讀 `settings/school`（**不走快取**，改完單位要立刻看到新值）
  組成 `orgCodes`，核對 `units[].orgUnit` 存在；GET 則兩份文件都走 `cachedSettingDoc`（30 秒）。
- 其他：`assertSameOrigin`、限流 `SCHOOL_SPACES_GET`（60/分）／`SCHOOL_SPACES_MUTATE`（20/分）、
  稽核 `logActivity("school_spaces_updated")`（details 記層數與空間數）、`Cache-Control: no-store`。

## 伺服器驗證規則

`validateSpaceStructure()`（API 與表單共用，任一不過即 400）：

1. `levelCount` 為 1～6 的整數；`levelLabels` 長度＝層級數、每項非空 ≤ 20 字。
2. `units ≤ 500`；`code` 非空且全域唯一；`name` 非空 ≤ 40 字，**同一上級空間內唯一**；
   `nameEn` ≤ 60 字（可空白）；`spaceCode` ≤ 20 字（可空白，**填寫時全校唯一**，表格會即時標紅重複）；
   `floor` ≤ 20 字（可空白）。
3. `level` 在 1..levelCount 之內。
4. `level === 1 ⇔ parent === null`。
5. `parent` 必須存在，且 `parent.level === unit.level - 1`
   （**此條同時封死環狀引用**：要成環需無限往下）。
6. `orgUnit` 為 null 或 ≤ 64 字的代碼；給值時必須存在於單位層級設定（API 傳入 `orgCodes` 時核對）。
7. `capacity` 為 null 或 0～999 的整數；`notes` ≤ 200 字。
8. 無子空間才可刪除（前端先擋，伺服器同規則）。

## 搬移規則（與單位層級設定共用同一套語意）

改上級或層級時，**整棵子樹一起平移**（`setSpaceParent`／`setSpaceLevel`）：

- 新層級由上級推導：`parent ? parent.level + 1 : 1`。
- 上級不可是自己或自己的後代。
- 平移後最深層 > `levelCount` → 拒絕。
- 新空間插到新上級的**子層末尾**（兄弟順序＝陣列相對順序）。
- 同層順位可用表格的「上移／下移」對調（端點停用），
  視覺化檢視則可拖到**卡片間空隙**直接插到指定位置（`placeSibling`，同一套搬移限制）。
- 表格直接改「層級」時，若原上級不符新層級則**暫留空**，
  由驗證回報「未指定上級空間」擋住儲存，直到補選。

## 介面

頂部控制列（兩種檢視共用）：

- **空間層級數**（1～6）與**各層名稱**。縮小層級數時若仍有空間在更高層 → 拒絕並列出那些空間。
- 檢視切換「表格／視覺化」、**還原**（放棄未存變更）、**儲存變更**（未變更或驗證不過時停用）。
- 驗證訊息即時顯示；未存變更以文字提示。
- **表格下方另有一組**儲存／還原按鈕與訊息區（空間多、捲到下方時不必再捲回頂部）。

**A. 表格檢視**（`SchoolSpacesTable.tsx`，同時是行動裝置與無障礙路徑）：
欄位以**上下兩列整併**呈現（間距 2px），節省水平空間：

| 欄位 | 行為 |
|---|---|
| 層級 | 下拉 1..N（顯示層名）；改變即連動子樹 |
| 空間代碼／樓層 | 上列＝空間代碼（≤ 20 字，可空白；全校唯一，重複即時標紅）；下列＝樓層（≤ 20 字，可空白，如「3F」「B2」） |
| 中文名稱／英文名稱 | 上列＝中文名稱（≤ 40 字，空白列擋存）；下列＝英文名稱（≤ 60 字，可空白） |
| 上級空間／隸屬單位 | 上列＝上級空間下拉**只列出上一層**的空間（第 1 層固定「（最上層）」且停用；缺上級時標紅「請選擇上級空間」）；下列＝隸屬單位下拉（選自單位層級設定，「（隸屬單位未指定）」＝ null）。**有下級的單位以 `optgroup` 分組**（如「教務處」下含教學組、註冊組…，下級自動縮排；
單位本身為分組內第一項、標示為「○○（本單位）」以免與分組標題重複），第 3 層以下以「└」前綴攤平在所屬分組內；無下級的單位維持平面選項 |
| 開放借用／容納人數 | 上列＝「開放借用」核取方塊（預設勾選）；下列＝容納人數（0～999，留空＝未填寫） |
| 設備說明 | 直接編輯（≤ 200 字，可空白） |
| 操作 | 無框純圖示鈕（滑鼠移入顯示提示）：上移／下移（同層對調，端點停用）、＋子空間（已達層級上限則停用）、刪除（紅色，有子空間會被擋） |

**B. 視覺化檢視**（`SpaceTree.tsx`，第 1 層母艦 + 原生 HTML5 拖曳）

- 以**第 1 層空間為母艦**：每個空間一張卡片，第 2 層卡片巢狀放在母艦內，
  第 3 層以下依此類推（左側縱線表示層級關係）。
- **卡片顯示中文名稱**（有空間代碼時一併顯示「名稱（代碼）」）；
  新增、改名、屬性編輯、刪除與上移／下移請用表格檢視。
- 拖曳時卡片之間會出現**空隙**（拖曳中略微加高）：
  - 拖到**空隙**＝插到該位置（`placeSibling`，同層換位；也可跨層搬入），
    例如把第 1 層的 A 拖到 B、C 之間 → 順位變 B、A、C。
  - 拖到**另一張卡片**＝設為其下級（排到該上級末尾，連同整棵子樹平移）。
  - 拖到**最外層虛線空白處**＝設為最上層（排到末尾）。
- 空隙位置以「不含被拖曳空間」的順序計算，故同層拖曳的插入點不會差一格。
- 禁止拖入自己或後代、禁止使子樹超出層級數（不接受放置，不做任何變更）。
- 放置中的目標以主題色外框或色塊提示（`box-shadow`／`background: var(--primary)`）。
- **行動裝置不支援 HTML5 拖曳**，請改用表格檢視。

兩種檢視共用**同一份未儲存狀態與單一儲存鈕**，切換不會遺失內容。

## 與其他功能的關係

- **行事曆**：事件的 `location` 目前是自由文字（≤ 120 字）。
  日後可讓地點欄位下拉選單引用本清單的空間名稱（保持自由文字可輸入，向後相容）。
- **學校空間預約模組**（`spaceBooking`，`feature-modules.ts` 中 `status: "planned"`）：
  日後應以 `cachedSettingDoc(SPACES_DOC_ID)` 讀本文件、
  以 `code` 引用空間、以 `openForBooking` 過濾可借空間，
  預約成立後經 `publishScheduleFromModule()` 發佈到行事曆。
- **單位層級設定**：`orgUnit` 欄位引用其單位 `code`；單位改名不追溯、
  刪除單位不連動刪除空間（空間上會殘留不存在的代碼，介面顯示為「（未指定）」以外的原始值由驗證擋存）。
- **年段班級設定待辦「教室」**：日後班級的教室欄位可改為引用本清單的空間 `code`。
- **不變項**：超級屬性的層級守門、`schoolSettings` 超級專屬、
  `settings/system` 的覆寫保留行為，皆不因本功能改變。

## 驗收清單

1. 一般管理員看不到「學校基本設定」首頁卡片；直開 `/admin/school-settings` 或
   `/admin/school-settings/spaces` 顯示「權限不足」；`GET/PUT /api/admin/school/spaces` 回 403。
2. 調整層級數與各層名稱 → 儲存後重新整理仍在。
3. 表格：新增最上層空間、設上級、改層級（子樹連動）、補選上級後可儲存；
   「上移／下移」只動同層順位，首末筆按鈕停用。
4. 視覺化：第 1 層 A、B、C，把 A 拖到 B、C 之間的空隙 → 順位變 B、A、C；
   把某空間拖進另一張卡片 → 巢狀位置跟著移；拖到最外層空白 → 回到第 1 層末尾。
   拖入自己的後代 → 無反應；搬移會超出層級數 → 訊息拒絕。
5. 中文名稱、英文名稱、空間代碼、樓層、容納人數、設備說明可直接編輯並儲存；
   同一上級下中文名稱重複、或空間代碼全校重複 → 驗證訊息擋存（代碼欄即時標紅）。
6. 「隸屬單位」下拉顯示單位層級設定的單位，有下級的單位（如教務處）以 `optgroup` 分組、
   下級縮排顯示；選定後儲存、重新整理仍在。
   單位層級設定刪掉某單位後重新儲存空間 → 400「隸屬單位不存在」。
7. 「開放借用」取消勾選 → 儲存後狀態保留。
8. 刪除有子空間者 → 訊息拒絕；縮小層級數但仍有更高層空間 → 拒絕並列出空間名稱。
9. 「儲存變更」後稽核紀錄出現 `school_spaces_updated`；空間多時捲到表格底部，
   底部的「儲存變更」與儲存訊息同樣可用、不需捲回頂部。
10. **存一次「系統設定」不會清掉空間資料**（不同文件）。

## 待辦（本輪未做）

- 行事曆地點欄位引用空間清單（下拉＋自由文字）。
- 空間預約模組（`spaceBooking`）接本清單。
- 年段班級設定的「教室」欄位引用空間 `code`。
- 校區欄位（引用校務基本資料的校區）——目前以最上層空間表達校區即可。
- 匯入／匯出。
