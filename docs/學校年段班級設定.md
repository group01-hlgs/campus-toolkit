# 學校年段班級設定（年段班級設定）

「學校基本設定」`schoolSettings`（僅超級管理員）底下的子功能，
子功能代碼 `schoolSettings.classes`。
登記本校的年段劃分、各年段涵蓋的年級，以及每年級的班級清單（班級代碼與班級名稱）。

- **入口**：管理員首頁 →「學校基本設定」卡片 → 子功能入口卡片「年段班級設定」
  → `/admin/school-settings/classes`。
  「學校基本設定」頁（`/admin/school-settings`）本身是**子功能入口卡片牆**，
  版頭、權限閘門與頁尾由共用 `school-settings/layout.tsx` 提供，新增子功能＝加一張卡片＋一個子路由。
- **結構性資料、不按學期、全校一份**：學期轉換不會影響，也不按校區分開；
  與 `roleEnabled` 同屬現行狀態。
- **供日後引用**：名冊的年級（`grade`）、班級代碼（`classCode`）、班級名稱（`className`）
  欄位日後可改為取自本設定（目前尚無取用點）。

## 名詞

| 名詞 | 說明 |
|---|---|
| 年段 | 自訂的年級區段（如「低年段」「國小部」），名稱由管理人員填寫，可選綁定教育階段 |
| 年級 | 1～12 的年級數字；同一年級**只能歸屬一個年段** |
| 班級代碼 | 班級的識別代碼，**全校不可重複**（日後對應名冊 `classCode`） |
| 班級名稱 | 班級的顯示名稱，**同一年級內不可重複**（日後對應名冊 `className`） |
| 綁定學制 | 年段可選綁一個教育階段（國民小學／國民中學／高級中等學校／大專院校）或「不綁定」；僅供日後對照，不會自動展開年級 |

## 資料模型

存於 **`settings/schoolClasses`**（與 `settings/system`、`settings/school`、
`settings/schoolProfile` 同集合的獨立文件）。

- 刻意不放 `settings/system`：系統設定的 PUT 是整份覆寫（只保留 `roleEnabled`），
  混放會在下次儲存系統設定時被清掉。
- 刻意不放 `settings/school`（單位層級）與 `settings/schoolProfile`（校務基本資料）：
  兩者的 PUT 同樣是整份 `set()` 覆寫，放同一文件會互相清掉，因此各佔一份文件。

```ts
interface ClassRow {
  id: string;    // 穩定代碼：新增時產生、改名不變（cl_ 前綴）
  code: string;  // 班級代碼，≤ 20 字、全校不可重複
  name: string;  // 班級名稱，≤ 40 字、同年級內不可重複
}
interface GradeRow {
  grade: number;         // 1～12，同一年段內升冪、全校唯一
  classes: ClassRow[];   // 該年級的班級；兄弟順序＝陣列相對順序
}
interface Segment {
  id: string;                // 穩定代碼：新增時產生、改名不變（s_ 前綴）
  name: string;              // 年段名稱，≤ 20 字、不可重複
  stage: StageValue | null;  // 綁定學制（可 null＝不綁定）
  grades: GradeRow[];        // 涵蓋年級，至少 1 個、升冪
}
interface SchoolClassesSetting {
  segments: Segment[];       // 1～6 個年段（可暫時為 0 個）；兄弟順序＝陣列相對順序
}
```

- 常數與型別：`src/types/school-classes.ts`（**不含 `server-only`**，前端與 API 共用驗證）。
- 空庫＝`{ segments: [] }`（介面顯示空狀態引導）。
- 上限常數：`CLASSES_MAX_SEGMENTS = 6`、`CLASSES_MAX_CLASSES_PER_GRADE = 30`、
  `CLASSES_MAX_CLASSES = 300`、`CLASSES_MAX_GRADE = 12`。
- `StageValue` 與 `EDUCATION_STAGES` 引自 `src/types/school-profile.ts`，
  但**兩份文件各自獨立**：校務基本資料不存在時本頁仍可正常運作。

## API

`src/app/api/admin/school/classes/route.ts`

| 方法 | 行為 |
|---|---|
| `GET` | 讀回資料；`readSchoolClasses()` 寬容修正型別與範圍（補 id、去重、年級排序），毀損不整份作廢 |
| `PUT` | body `{ setting }`，整份覆寫 `settings/schoolClasses`；驗證不過回 400 且不寫入 |

- 守門：`requireAdminModule("schoolSettings")` —— `adminModulesOf` 對非超級一律剝除
  該模組，因此等同「僅超級管理員」，與頁面層判斷同一把尺。
- 其他：`assertSameOrigin`、限流 `SCHOOL_CLASSES_GET`（60/分）／`SCHOOL_CLASSES_MUTATE`（20/分）、
  稽核 `logActivity("school_classes_updated")`（details 記年段數與班級數）、`Cache-Control: no-store`。

## 伺服器驗證規則

`validateSchoolClasses()`（API 與表單共用，任一不過即 400）：

1. `segments` 至多 6 個；每段 `id` 非空且全域唯一、`name` 非空 ≤ 20 字且不可重複。
2. `stage` 為 `null`（不綁定）或已知的教育階段值。
3. `grades` 每段至少 1 個；`grade` 為 1～12 的整數、段內升冪且不可重複；
   **同一年級不可同時出現在兩個年段**。
4. 每年級 `classes` 至多 30 筆、全校總數至多 300 筆；
   `id` 非空且全域唯一；`code` 非空 ≤ 20 字且**全校唯一**；
   `name` 非空 ≤ 40 字且**同年級內唯一**。

## 介面

`src/components/SchoolClassesEditor.tsx`，沿用校務基本資料的 **saved／draft** 模式：
頂部為**新增年段**、年段與班級計數（`年段 n / 6，班級 n / 300`）、
**還原**（放棄未存變更）與**儲存變更**（未變更或驗證不過時停用），
驗證訊息即時顯示、未存變更以文字提示。年段以卡片呈現，每張卡片包含：

1. **標題列**：年段名稱輸入（≤ 20 字）、學制下拉（不綁定＋四個教育階段）、
   上移／下移（調整年段順序，抵達端點時停用）、刪除年段。
2. **各年級列**：年級標題與班級數；每班一列「班級代碼＋班級名稱＋移除」，
   「新增班級」受每年級 30 班上限約束；「刪除年級」在該年級尚有班級時需二次確認。
3. **底部新增年級**：年級下拉列出**尚未被任何年段占用**的年級（1～12）＋「新增年級」；
   12 個年級全數占用時按鈕停用。新增年段時自動帶入第一個未占用年級，
   因此 UI 不會產生跨年段重複的年級。

刪除年段在尚有班級時需二次確認（`window.confirm`）。
**儲存過場**：按下「儲存變更」後先顯示全螢幕遮罩（轉圈＋「儲存中，請稍候…」，
`animate-fade-in` 淡入、阻擋重複操作），伺服器回應後切換為**結果視窗**
（成功綠勾／失敗紅叉，同樣淡入動畫），**停留 2 秒後自動關閉**，點擊背景可立即關閉；
計時器在重複呼叫時會重置，元件卸載時清除。

## 與其他功能的關係

- **不與其他設定混放**：`settings/schoolClasses` 與 `settings/system`、`settings/school`、
  `settings/schoolProfile` 各自獨立文件，任一方的整份覆寫都不會清掉本資料。
- **與校務基本資料僅共享型別**：年段綁定學制用的 `StageValue`／`EDUCATION_STAGES` 引自
  `school-profile.ts`，但不讀取其資料；校務基本資料未填不影響本頁運作。
- **與身分名冊的關係（尚未串接）**：名冊的 `grade`／`classCode`／`className`
  目前仍是自由文字欄（`src/types/roster.ts`），日後可改為下拉選單並取自本設定。
- **不變項**：超級屬性的層級守門、`schoolSettings` 超級專屬、
  `settings/system` 的覆寫行為，皆不因本功能改變。

## 驗收清單

1. 一般管理員看不到「學校基本設定」首頁卡片；直開 `/admin/school-settings/classes`
   顯示「權限不足」；`GET/PUT /api/admin/school/classes` 回 403。
2. 「新增年段」自動帶入未占用年級 → 改名、加班級、儲存後重新整理仍在。
3. 「新增年級」下拉只列出尚未被其他年段占用的年級；12 個年級用完後按鈕停用。
4. 年段數量到 6 個後「新增年段」停用；每年級加到 30 班後「新增班級」停用。
5. 班級代碼留白或重複（跨年級）、同年級班級名稱重複、年段名稱重複 → 驗證訊息擋下儲存。
6. 直接 `PUT` 送入跨年段重複的年級或超過上限的數量 → 回 400 且不寫入。
7. 刪除尚有班級的年段／年級 → 彈出確認對話框，取消則不變更。
8. 年段「上移／下移」調整順序 → 儲存後重新整理順序維持。
9. 「儲存變更」後稽核紀錄出現 `school_classes_updated`。
10. 儲存時先出現「儲存中，請稍候…」過場遮罩，完成後跳出結果視窗並在 2 秒後自動關閉；
    失敗時同樣以紅叉視窗顯示錯誤訊息。
11. **存一次「系統設定」「單位層級設定」或「校務基本資料」不會清掉年段班級設定**（不同文件）。

## 待辦（本輪未做）

- 依校務基本資料的教育階段與年制**自動產生**年段與年級（目前需逐段手動新增）。
- 班導師、啟用狀態、教室、備註等額外班級欄位。
- 按校區分開設定班級（引用 `schoolProfile.campuses[].id`）。
- 依學期保存班級異動（目前為結構性資料、不按學期）。
