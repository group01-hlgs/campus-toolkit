# 學校年段班級設定（年段班級設定）

「學校基本設定」`schoolSettings`（僅超級管理員）底下的子功能，
子功能代碼 `schoolSettings.classes`。
登記本校的年段（**一個年段＝一個年級**，如「高一」）、各年級的代碼與名稱，
以及每年級的班級清單（班級代碼＋班級名稱；高級中等學校學制另有群別、科別）。
介面依校務基本資料的**學制分區**，學制由年級編號自動推導，不必在年段上另選。

- **入口**：管理員首頁 →「學校基本設定」卡片 → 子功能入口卡片「年段班級設定」
  → `/admin/school-settings/classes`。
  「學校基本設定」頁（`/admin/school-settings`）本身是**子功能入口卡片牆**，
  版頭、權限閘門與頁尾由共用 `school-settings/layout.tsx` 提供，新增子功能＝加一張卡片＋一個子路由。
- **結構性資料、不按學期、全校一份**：學期轉換不會影響，也不按校區分開。
- **上限取自校務基本資料**：可建立的學制、年級編號範圍、年級總數上限**與年段數量上限**，
  全部由 `settings/schoolProfile` 的教育階段與年制總和決定（見「與其他功能的關係」）。
- **供日後引用**：名冊的年級（`grade`）、班級代碼（`classCode`）、班級名稱（`className`）
  欄位日後可改為取自本設定（目前尚無取用點）。

## 名詞

| 名詞 | 說明 |
|---|---|
| 年段 | **＝一個年級**（如「高一」「國一」），一對一對應 `grades` 的一筆；學制不另存，由年級編號推導 |
| 學制 | 即教育階段：國民小學／國民中學／高級中等學校／大專院校，須為校務基本資料**已勾選**者；介面依學制分區顯示 |
| 年級編號 | 系統內部編號，落在該學制的全校編號範圍內且**全校唯一**、由小到大，僅用於排序、推導學制與產生預設值 |
| 年級代碼 | 年級的識別代碼，預設＝年級編號，**全校不可重複**、可編輯 |
| 年級名稱 | 年級的顯示名稱，預設依「年級名稱預設」慣例產生（學制內序號或全域編號），**同學制內不可重複**、可編輯 |
| 班級代碼 | 班級的識別代碼，**全校不可重複**（日後對應名冊 `classCode`） |
| 班級名稱 | 班級的顯示名稱，**同一年級內不可重複**（日後對應名冊 `className`） |
| 群別／科別 | **僅高級中等學校學制**的班級可填寫，各為「代碼＋名稱」，選填但兩者需同時填寫 |
| 年級名稱預設 | 本設定的選項，決定**之後新增**年級的名稱預設值；不改動既有名稱（見下節） |

### 年段＝年級（為何不讓年段含多個年級）

早先版本讓一個年段包 1 個或多個年級（「低年段」含 1～2 年級），但現場的年段叫法
（高一、國一、低年段）本質上都對應到年級，於是「年段名稱」「學制」「涵蓋年級」三處要重複描述同一件事。
故改為**一個年段＝一個年級**：`grades` 攤平到頂層，年段就是表格中的一個區塊。

| 舊結構 | 新結構 |
|---|---|
| `segments: { id, name, stage, grades[] }[]` | `grades: { id, grade, code, name, classes[] }[]` |
| 年段自訂名稱＋自選學制 | 年段名稱＝年級名稱；學制由年級編號推導 |
| 年級編號在段內升冪 | 年級編號全校升冪（read 會排序） |

- 讀回舊資料自動攤平：`readSchoolClasses`／`validateSchoolClasses` 都先經 `collectRawGrades`
  收集頂層 `grades`，沒有則取舊版 `segments[].grades`，**不需資料遷移**。
- 介面改為**依學制分區**：每學制一塊，標題顯示「年制 N 年、年級編號 a～b、已建立 n / N 個年段」，
  分區內不再出現學制欄位，「新增年段」按鈕放在各分區內。

### 年級名稱預設（學制內序號 vs 全域編號）

現場兩種叫法都有：「一年級／二年級／三年級」（學制內序號）與「十年級／十一年級／十二年級」
（全域編號，等同年級編號）。故本設定頂部提供「年級名稱預設」切換：

| 選項 | 國小（編號 1～6） | 國中（編號 7～9） | 高中職（編號 10～12） |
|---|---|---|---|
| `local` 學制內序號（預設） | 1～6 年級 | 1～3 年級 | 1～3 年級 |
| `global` 全域編號 | 1～6 年級 | 7～9 年級 | 10～12 年級 |

- 只影響**之後按各學制分區「新增年段」產生的名稱預設值**，既有名稱一律不改寫。
- 年級**代碼**的預設永遠等於年級編號（7／10…），不受此選項影響。
- 兩種模式下同名都可能發生（如國小「1 年級」與國中「1 年級」分屬不同學制），
  故年級名稱只需**同學制內唯一**（`local` 模式下天然不重複，`global` 模式同理）。

### 學制的年級編號範圍

年級編號依校務基本資料的**學制順序**連續展開，各學制佔一段連續區間；
`gradeRangeOf` 給出該學制的範圍、`stageOfGrade` 反過來由編號推導學制，
因此各分區按「新增年段」自動帶入的編號與預設名稱都是可預期的：

| 依序勾選的學制 | 年制 | 年級編號範圍 |
|---|---|---|
| 國民小學 | 6 | 1～6 |
| 國民中學 | 3 | 7～9 |
| 高級中等學校 | 3 | 10～12 |
| 大專院校 | 4 | 13～16 |

## 資料模型

存於 **`settings/schoolClasses`**（與 `settings/system`、`settings/school`、
`settings/schoolProfile` 同集合的獨立文件）。

- 刻意不放 `settings/system`：系統設定的 PUT 是整份覆寫（只保留 `roleEnabled`），
  混放會在下次儲存系統設定時被清掉。
- 刻意不放 `settings/school`（單位層級）與 `settings/schoolProfile`（校務基本資料）：
  兩者的 PUT 同樣是整份 `set()` 覆寫，放同一文件會互相清掉，因此各佔一份文件。
  但**本頁的上限依賴校務基本資料**，故驗證需帶上下文（見 API）。

```ts
interface VocField { code: string; name: string }          // 群別／科別
interface ClassRow {
  id: string;                    // 穩定代碼：新增時產生、改名不變（cl_ 前綴）
  code: string;                  // 班級代碼，≤ 20 字、全校不可重複
  name: string;                  // 班級名稱，≤ 40 字、同年級內不可重複
  group: VocField | null;        // 群別（僅高級中等學校學制；其餘一律 null）
  department: VocField | null;   // 科別（僅高級中等學校學制；其餘一律 null）
}
interface GradeRow {
  id: string;                    // 穩定代碼（g_ 前綴）
  grade: number;                 // 年級編號：落在學制範圍內、全校唯一、由小到大
  code: string;                  // 年級代碼，≤ 10 字、全校不可重複
  name: string;                  // 年級名稱，≤ 20 字、同學制內不可重複
  classes: ClassRow[];           // 該年級的班級；**陣列順序＝班級順位**（有意義，見下）
}
interface SchoolClassesSetting {
  grades: GradeRow[];            // 年段（＝年級）清單，0～年制總和 筆，全校升冪
  nameStyle: "local" | "global";  // 年級名稱預設慣例（缺省視為 local）
}

/** 驗證上下文：取自校務基本資料 settings/schoolProfile */
interface SchoolClassesContext { stages: { stage: StageValue; years: number }[] }
```

- 常數與型別：`src/types/school-classes.ts`（**不含 `server-only`**，前端與 API 共用驗證）。
- 空庫＝`{ grades: [], nameStyle: "local" }`（介面顯示空狀態引導）。
- 語意上限（依校務基本資料）：年段數 ≤ **年制總和**；結構上限：
  `CLASSES_MAX_CLASSES_PER_GRADE = 30`、`CLASSES_MAX_CLASSES = 300`、
  `CLASSES_MAX_GRADE = 24`（僅 read 的寬容範圍）。
  **年段不另設固定上限常數**（早先的 6 段已移除）。
- **學制不另存**：`stageOfGrade(context, grade)` 由年級編號落在哪一段範圍推導，
  介面依此把年段排進各學制分區，避免兩處各存一份而不同步；
  讀回舊資料時 `segments[].stage` 一律忽略（以校務基本資料的年制重算）。
- **相容舊資料**：`collectRawGrades(data)` 收集頂層 `grades`，未提供才取 `segments[].grades`
  攤平使用，`readSchoolClasses` 與 `validateSchoolClasses` 都走同一條路，舊文件免遷移即可讀寫
  （下一次儲存即寫回新結構）。
- **班級順位＝`classes` 陣列順序**：同一年級內的班級有前後順位，介面可用「前移／後移」調整，
  讀寫與驗證都**不重排**（保序）。日後顯示全年段班級時，預設即依「年級編號 → 班級順位」排序，
  故順位是資料的一部分，不可當成無意義的顯示順序。
- `readSchoolClasses(raw, context?)` 寬容讀回：補 `id`、補年級代碼／名稱預設值
  （依 `nameStyle`）、去重、年級排序、**依推導出的學制決定是否保留群別與科別**
  （非高級中等學校學制丟棄）；
  語意問題（編號超出範圍、代碼重複…）交由驗證回報，毀損不整份作廢。

## API

`src/app/api/admin/school/classes/route.ts`

| 方法 | 行為 |
|---|---|
| `GET` | 讀回 `{ setting, stages }`；`setting` 經 `readSchoolClasses(setting, context)` 寬容修正，`stages` 為校務基本資料的學制與年制（前端驗證與介面共用，不需另打一發請求） |
| `PUT` | body `{ setting }`，整份覆寫 `settings/schoolClasses`（寫入 `nameStyle` 與 `grades`）；以伺服器端讀到的 `context` 驗證，不過即 400 且不寫入；回 `{ setting, stages }` |

- 守門：`requireAdminModule("schoolSettings")` —— `adminModulesOf` 對非超級一律剝除
  該模組，因此等同「僅超級管理員」，與頁面層判斷同一把尺。
- 其他：`assertSameOrigin`、限流 `SCHOOL_CLASSES_GET`（60/分）／`SCHOOL_CLASSES_MUTATE`（20/分）、
  稽核 `logActivity("school_classes_updated")`
  （details 記年段數與班級數）、`Cache-Control: no-store`。

## 伺服器驗證規則

`validateSchoolClasses(raw, context)`（API 與表單共用，任一不過即 400）：

1. `nameStyle` 若存在須為 `local` 或 `global`（缺省＝`local`，回傳值一律補齊）。
2. 資料先經 `collectRawGrades` 攤平：優先取頂層 `grades`，未提供才取舊版 `segments[].grades`；
   攤平後為空 → 直接回 `ok`（空設定合法，不進後續檢查）。
3. 有年段但 `context.stages` 為空 → 提示先至校務基本資料勾選教育階段與年制。
4. 年段數 ≤ **校務基本資料的年制總和**（超過即回「年段數量（n）超過校務基本資料的年制總和（m）」）。
5. 逐筆年段（＝年級）：`id` 非空且全域唯一；
   `grade` 為 1～24 的整數、**由小到大且不可重複**、不超過年制總和，
   再用 `stageOfGrade(context, grade)` 推導所屬學制（推不出即擋下）。
6. `code`（年級代碼）非空 ≤ 10 字且**全校唯一**（重複訊息會指出原編號）；
   `name`（年級名稱）非空 ≤ 20 字且**同學制內唯一**（不同學制可同名）。
7. 每年級 `classes` 至多 30 筆、全校總數至多 300 筆；
   `id` 非空且全域唯一；`code`（班級代碼）非空 ≤ 20 字且**全校唯一**；
   `name`（班級名稱）非空 ≤ 40 字且**同年級內唯一**。
8. 群別／科別：代碼 ≤ 20 字、名稱 ≤ 40 字，**代碼與名稱需同時填寫**（皆空白＝未填）；
   **推導學制非高級中等學校的班級出現群別或科別即擋下**。

## 介面

`src/components/SchoolClassesEditor.tsx`，沿用校務基本資料的 **saved／draft** 模式，
驗證訊息即時顯示、未存變更以文字提示。

**驗證錯誤訊息固定可見**：錯誤以 `.sticky-alert`（`position: sticky; top: 0`、
不透明 `var(--card)` 底＋陰影）釘在畫面上方——列表過長往下捲時訊息仍跟著畫面，
半透明警示底色會讓下方列表文字透出來，故外層另給不透明底、內層才是警示框。
訊息本身已帶年段／年級／班級名稱，可直接對照到出錯處。

**頂部列**：「年級名稱預設」下拉（學制內序號／全域編號）、
計數「年段 n / 年制總和 m，班級 n / 300」、**還原**與**儲存變更**
（未變更或驗證不過時停用）。**學制不在這裡選**（分區內各有「新增年段」按鈕）。
校務基本資料未勾任何學制時，顯示紅色提示並提供「前往校務基本資料」按鈕，
各分區都不會出現、無處新增年段。

**學制分區**：依 `context.stages` 逐學制一塊，每塊的標題列顯示學制名稱、
「年級編號 a～b（年制 N 年）」、「已建立 n / N 個年段」與該分區的**「新增年段」**按鈕
（該學制編號用完即停用）；高級中等學制分區附「群別／科別為選填」說明。
年級編號落在任何學制範圍之外的年段（年制或勾選的學制後來被異動）不會排進任何分區，
改由區塊下方的紅色清單列出並提供**逐筆刪除**按鈕，否則驗證擋下無法儲存。

**新增年段**：每次只建立 **1 個年段（＝1 個年級）**，帶入該學制第一個尚未占用的編號，
年級代碼自動給年級編號、年級名稱依「年級名稱預設」產生（`local`＝學制內序號、`global`＝全域編號）。
在同分區連按即可依序建出高一／高二／高三（編號 10、11、12）。

**表格（年段與班級攤平成一張表）**：每個學制分區內是一張表格，欄位為
`年級編號｜年級代碼｜年級名稱｜班級代碼｜班級名稱｜（群別｜科別，僅高級中等學校）｜操作`。

1. **年段＝表格中的一個區塊**：前三欄（年級編號唯讀、年級代碼、年級名稱輸入框）
   以 `rowSpan` 跨過該年級的全部班級列，年級與其班級在同一水平線上可直接對照；
   **沒有學制欄位、也沒有年段上移／下移**（年段固定依年級編號排序）。
   表格過寬時外層 `overflow-x-auto` 橫向捲動（`min-w-[720px]`）。
2. **班級列**：每班一列——`班級代碼`＋`班級名稱`＋（高級中等學校的）群別／科別代碼與名稱，
   `操作`欄為 `前移`／`後移`／`移除`，前後移動＝調整班級順位，兩端的按鈕停用。
3. **年段操作列**：每個年段的最後一列是跨全部欄位的列，放 `n 班`＋`新增班級`＋`刪除年段`；
   班級超過 1 筆時同列加註「班級順位＝由上到下的順序」。
   沒有班級的年段只有一列：前三欄照常（可改代碼／名稱），其餘欄位合併顯示
   「尚未建立班級。」＋同兩個按鈕。
4. 表頭列 `bg-hover` 底、年段操作列用較粗的上框線分隔，取代原本的卡片框線。

刪除年段在尚有班級時需二次確認（`window.confirm`）。
**儲存過場**：按下「儲存變更」後先顯示全螢幕遮罩（轉圈＋「儲存中，請稍候…」，
`animate-fade-in` 淡入、阻擋重複操作），伺服器回應後切換為**結果視窗**
（成功綠勾／失敗紅叉，同樣淡入動畫），**停留 2 秒後自動關閉**，點擊背景可立即關閉；
計時器在重複呼叫時會重置，元件卸載時清除。

## 與其他功能的關係

- **硬依賴校務基本資料**：可建立的學制、年級編號範圍與**年段數量上限**
  （＝年制總和）都取自 `settings/schoolProfile` 的 `stages`（學制與年制），
  所屬學制更直接由年級編號推導（`stageOfGrade`）。
  校務基本資料未勾任何學制時本頁無法建立年段；
  學制或年制被異動後，超出範圍的年段會被列進紅色清單，需逐筆刪除或回校務基本資料調整。
- **不與其他設定混放**：`settings/schoolClasses` 與 `settings/system`、`settings/school`、
  `settings/schoolProfile` 各自獨立文件，任一方的整份覆寫都不會清掉本資料。
- **與身分名冊的關係（尚未串接）**：名冊的 `grade`／`classCode`／`className`
  目前仍是自由文字欄（`src/types/roster.ts`），日後可改為下拉選單並取自本設定。
- **不變項**：超級屬性的層級守門、`schoolSettings` 超級專屬、
  `settings/system` 的覆寫行為，皆不因本功能改變。

## 驗收清單

1. 一般管理員看不到「學校基本設定」首頁卡片；直開 `/admin/school-settings/classes`
   顯示「權限不足」；`GET/PUT /api/admin/school/classes` 回 403。
2. 校務基本資料未勾任何學制 → 本頁顯示提示與「前往校務基本資料」按鈕，
   **不出現任何學制分區**、無處新增年段。
3. 校務基本資料勾「國民小學 6 年」→ 出現「國民小學」分區（年級編號 1～6、已建立 0 / 6）；
   按分區內「新增年段」建立 **1 個年段（＝1 個年級）**（編號 1、代碼 1、名稱「1 年級」），
   連按可補到 1～6，補滿後按鈕停用。
4. 再勾「國民中學 3 年」→ 出現「國民中學」分區（年級編號 7～9），新增年段帶入編號 7、代碼 7；
   頂部計數為「年段 1 / 9，班級 0 / 300」。
5. 年級代碼／名稱可即時修改並儲存；年級代碼全校重複、名稱留白或**同學制內**重複 → 驗證擋下；
   不同學制可同名（國小「1 年級」與國中「1 年級」並存）。
6. 刪除一個年段後，同分區「新增年段」可補回被刪的編號；補滿後按鈕停用（該學制編號已用完）。
7. 高級中等學校 3 年：在該分區**連按 3 次「新增年段」** → 產生 3 個年段
   （編號 10、11、12，各含 1 個年級）；第 4 次時該分區已無可用編號、按鈕停用。
8. 「年級名稱預設」切到「全域編號」後新增年段 → 名稱為「10 年級」「11 年級」；
   切回「學制內序號」只影響之後新增，既有名稱不被改寫；年級代碼一律仍等於年級編號；
   重新整理後選項維持（已隨設定儲存）。
9. 高級中等學校分區的班級出現群別／科別四欄，只填代碼不填名稱 → 驗證擋下；
   國民小學分區的班級不顯示該四欄，若資料帶入群別 → 驗證擋下（read 讀回時亦會丟棄）。
10. 直接 `PUT` 送入超出年制總和的年級編號、非升冪／重複的編號、同學制內重複的年級名稱，
    或年段數超過校務基本資料的年制總和 → 回 400 且不寫入。
11. 刪除尚有班級的年段 → 彈出確認對話框，取消則不變更。
12. **舊 `segments` 結構的資料**（年段包年級）讀回 → 自動攤平為年段＝年級、介面正常顯示，
    儲存後寫回 `grades` 新結構，不需人工遷移。
13. 把校務基本資料的年制縮短（如國小 6 → 4 年）→ 超出範圍的年段出現在紅色清單，
    逐筆刪除後才可儲存；頂部驗證訊息同步擋下。
14. 同一年級建 2 個以上班級 → 用「前移／後移」交換順位 → 儲存後重新整理順位維持；
    第一筆的「前移」與最後一筆的「後移」停用（只剩 1 筆時不出現順位提示）。
15. 造出驗證錯誤（如班級代碼重複）後往下捲動長列表 → 錯誤訊息仍釘在畫面上方可見，
    且底色不透明、列表文字不會透出來；修正後訊息消失、「儲存變更」恢復可按。
16. 「儲存變更」後稽核紀錄出現 `school_classes_updated`（details 含年段數與班級數）。
17. 儲存時先出現「儲存中，請稍候…」過場遮罩，完成後跳出結果視窗並在 2 秒後自動關閉；
    失敗時同樣以紅叉視窗顯示錯誤訊息。
18. **存一次「系統設定」「單位層級設定」或「校務基本資料」不會清掉年段班級設定**（不同文件）。
