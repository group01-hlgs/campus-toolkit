# 學校各式代碼表（各式代碼表）

「學校基本設定」`schoolSettings`（僅超級管理員）底下的子功能，
子功能代碼 `schoolSettings.codes`。
維護三份**代碼＋名稱**清單：**高級中等學校類型**、**群別**、**科別**，
作為**系統的基礎資料庫**：內建預設取自官方代碼表，各處（目前是校務基本資料的類型複選、
年段班級設定的班級群別／科別）都從這裡取用，同一組清單讓同一個 Firestore 的各分支共用。

- **入口**：管理員首頁 →「學校基本設定」卡片 → 子功能入口卡片「各式代碼表」
  → `/admin/school-settings/codes`。
  「學校基本設定」頁（`/admin/school-settings`）本身是**子功能入口卡片牆**，
  版頭、權限閘門與頁尾由共用 `school-settings/layout.tsx` 提供，新增子功能＝加一張卡片＋一個子路由。
- **僅超級管理員可編輯**：頁面層由 `layout.tsx` 的 `adminModules.includes("schoolSettings")` 擋，
  伺服器層由 `requireAdminModule("schoolSettings")` 擋（`adminModulesOf` 對非超級一律剝除該模組），
  兩者同一把尺。
- **結構性資料、不按學期、全校一份**：學期轉換不會影響，也不按校區分開。
- **基礎資料庫**：存 `settings/schoolCodes`（獨立文件），不與其他設定混放；
  分支（fork）連到同一個 Firestore 即共用同一組清單。

## 名詞

| 名詞 | 說明 |
|---|---|
| 高級中等學校類型 | 學校所屬類型（如普通型高中 `H`、技術型高中 `V`、進修部 `C`），與 GRP／DEP 頁的「課程類型」代碼一致 |
| 群別 | 技術型／綜合型高中等的「群」（如機械群、電機與電子群），班級可填的上層分類 |
| 科別 | 群底下的「科」（如機械科、資訊科）與各類學程（如 A01 機械技術學程），班級可填的下層分類 |
| 代碼表 | 本設定的內容：類型清單、群別清單與科別清單，各為一組 `{ 代碼, 名稱 }` |
| 官方代碼表 | 教育部「高級中等學校課程計畫平臺」代碼查詢頁的清單，內建預設即由此抓取 |
| 基礎資料庫 | 系統內各處共用的參考資料（本頁為類型／群別／科別），集中一處維護、各處取用 |

### 官方來源與內建預設

- 類型：`https://course.k12ea.gov.tw/courseinformation/QueryCode.asp?T=SCH`
- 群別：`https://course.k12ea.gov.tw/courseinformation/QueryCode.asp?T=GRP`
- 科別：`https://course.k12ea.gov.tw/courseinformation/QueryCode.asp?T=DEP`
- 內建於 `src/data/schoolCodesSeed.ts`（抓取於 2026-10-04）：
  **類型 8 筆、群別 21 筆、科別 340 筆**。官方表內群別代碼 `11`、`26` 各有兩筆不同名稱
  （學術群／學術學程、商業與管理群／商業群），屬不同課程類型，**同代碼不同名稱是合法的**。
- 文件不存在（新環境）→ `readSchoolCodes` 直接回內建清單，畫面與下拉立刻可用；
  舊文件缺少某欄（如加設 `schoolTypes` 之前存的）→ 該欄補內建清單，明確的空陣列則保留。
- 官方平台日後更新 → 重新抓取覆寫種子檔，頁面按「還原官方預設」帶入後「儲存變更」即更新。

## 資料模型

`settings/schoolCodes`（獨立文件，僅超級管理員可寫）：

```
settings/schoolCodes {
  schoolTypes: [{ code, name }],    // 高級中等學校類型清單（上限 50 筆）
  groups: [{ code, name }],         // 群別清單（上限 200 筆）
  departments: [{ code, name }]     // 科別清單（上限 1000 筆）
}
```

- 型別 `SchoolCodesSetting`、`VocCodeRow`；常數
  `CODES_DOC_ID = "schoolCodes"`、`CODES_VOC_CODE_MAX = 20`、`CODES_VOC_NAME_MAX = 40`、
  `CODES_MAX_SCHOOL_TYPES = 50`、`CODES_MAX_GROUPS = 200`、`CODES_MAX_DEPARTMENTS = 1000`
  （`src/types/school-codes.ts`）。
- **列沒有 `id`**：順位＝陣列順序，識別靠「代碼＋名稱」配對（判重用的就是這個配對）。
- 同代碼不同名稱允許（官方表即有）；代碼與名稱**都必填**（與班級的群別／科別規則一致）。
- `readSchoolCodes(raw)` 寬容讀回：逐筆去空白、留白該筆丟棄、配對重複只留第一筆、
  超長丟棄；三欄都不是陣列 → 回內建官方清單。
- 內建預設 `defaultSchoolCodes()`（複製種子檔，避免外部改動到內建值）。

## API

`src/app/api/admin/school/codes/route.ts`

| 方法 | 行為 |
|---|---|
| `GET` | 讀回 `{ setting }`；`setting` 經 `readSchoolCodes(...)` 寬容修正（文件不存在＝內建官方清單） |
| `PUT` | body `{ setting }`，整份覆寫 `settings/schoolCodes`（白名單寫入 `schoolTypes`、`groups`、`departments`）；以 `validateSchoolCodes` 驗證，不過即 400 且不寫入；回 `{ setting }` |

- 守門：`requireAdminModule("schoolSettings")` —— `adminModulesOf` 對非超級一律剝除
  該模組，因此等同「僅超級管理員」，與頁面層判斷同一把尺。
- 其他：`assertSameOrigin`、限流 `SCHOOL_CODES_GET`（60/分）／`SCHOOL_CODES_MUTATE`（20/分）、
  稽核 `logActivity("school_codes_updated")`（details 記類型、群別與科別筆數）、
  `Cache-Control: no-store`、`MAX_BODY = 400,000`（科別可達千筆）。

## 伺服器驗證規則

`validateSchoolCodes(raw)`（API 與表單共用，任一不過即 400，**整份不寫入**）：

1. `raw` 必須是物件（非陣列、非 null）。
2. `schoolTypes`、`groups` 與 `departments` **都必須是陣列**（缺一即回對應清單的「格式錯誤」）。
3. 筆數上限：類型 ≤ 50、群別 ≤ 200、科別 ≤ 1000（超過回「群別最多 200 筆」等）。
4. 逐筆：欄位必須是物件；`code`、`name` 都必須是**文字**；
   去頭尾空白後**都必填**；`code` ≤ 20 字、`name` ≤ 40 字。
5. **「代碼＋名稱」完全重複** → 擋下（訊息指出「群別「21 機械群」重複，請移除多餘的列」）；
   同代碼不同名稱**合法**。
6. 錯誤訊息帶列序號（如「第 3 筆科別未填代碼」），可直接對照畫面。

## 介面

`src/components/SchoolCodesEditor.tsx`，沿用其他學校基本設定子功能的
**saved／draft** 模式，驗證訊息以 `.sticky-alert` 釘在畫面上方、未存變更以文字提示。

**頂部列**：左側計數「內建預設取自課程計畫平臺（類型 n 筆、群別 n 筆、科別 m 筆）」，
右側三個按鈕：

1. **還原官方預設**：確認對話框後，以內建清單覆蓋目前草稿（**仍需按「儲存變更」才寫入**）。
2. **還原**：放棄未存變更（無變更時停用）。
3. **儲存變更**：未變更或驗證不過時停用。

**三區清單（高級中等學校類型清單、群別清單、科別清單）**：
各區**進入頁面時一律收合**，標題列為可按鈕（含箭頭圖示、`aria-expanded`／
`aria-controls`），標題旁顯示筆數 `n / 上限` 與「按標題展開」／「收合」提示，
右側**新增一列**（達上限停用；收合狀態下按新增會同時展開該區）。
展開後顯示**篩選框**（依代碼或名稱即時過濾）與表格，欄位 `代碼｜名稱｜操作`，
`操作`為`移除`。
空白列照常顯示，但代碼或名稱留白時驗證擋下無法儲存。
篩選無結果／清單為空時顯示說明文字（空清單可按「還原官方預設」帶回內建清單）。

**底部**：官方來源三條連結（類型代碼查詢／群別代碼查詢／科別代碼查詢）。
**儲存過場**：與年段班級設定相同——全螢幕遮罩（轉圈＋「儲存中，請稍候…」）
→ 結果視窗（成功綠勾／失敗紅叉）停留 2 秒自動關閉，點背景可立即關閉。

## 與其他功能的關係

- **年段班級設定（主要取用點）**：`SchoolClassesEditor` 與本設定**同時平行讀取**
  （一組 `Promise.all`，代碼表讀失敗只退回內建清單、**不擋**班級編輯）。
  高級中等學校班級的「群別」「科別」代碼欄是 `<input list>`＋`<datalist>`：
  - 選項 `voc-group-codes`／`voc-department-codes` 取自本設定（代碼＋名稱一起顯示）。
  - 代碼**完全比對**到表內一筆時**自動帶入名稱**——僅在名稱目前為空、
    或仍是表內某個官方名稱時才覆寫，避免打斷自行改過的名稱。
  - 仍**允許手動輸入表外的代碼／名稱**（驗證只要求兩者同時填寫，不要求存在於代碼表）。
  - 「高級中等學校類型」清單由**校務基本資料**取用：勾選高級中等學校後的
    類型複選（`seniorHighTypes`），平行讀取本清單、讀失敗退回內建清單、不擋編輯；
    選定值以「代碼＋名稱」存進 `settings/schoolProfile`（快照，日後改本清單不追溯）。
- **與校務基本資料／年段班級設定的差別**：那兩者決定「有哪些學制、年級、班級」，
  本頁只管「類型與班級的群別／科別候選值」；班級填的群別／科別內容存回
  `settings/schoolClasses`，本頁不存任何班級資料。
- **不與其他設定混放**：`settings/schoolCodes` 與 `settings/system`、`settings/school`、
  `settings/schoolProfile`、`settings/schoolClasses` 各自獨立文件，
  任一方的整份覆寫都不會清掉本資料。
- **不變項**：超級屬性的層級守門、`schoolSettings` 超級專屬、
  `settings/system` 的覆寫行為，皆不因本功能改變。

## 驗收清單

1. 一般管理員看不到「學校基本設定」卡片；直開 `/admin/school-settings/codes`
   顯示「權限不足」；`GET/PUT /api/admin/school/codes` 回 403。
2. 超級管理員由「學校基本設定」入口卡片（「各式代碼表」）進入本頁 →
   **三區清單預設全部收合**，只見標題與筆數。
3. 按標題展開「高級中等學校類型清單」→ 8 筆（H 普通型高中…G 建教合作班）；
   展開群別／科別清單 → **新環境（文件不存在）顯示內建官方清單**（群別 21 筆、科別 340 筆）。
4. 篩選框輸入「機械」→ 群別區只剩機械群／動力機械群等、科別區只剩機械相關科；
   清空回復全列表。
5. 「新增一列」→ 表尾多一列空白（收合狀態按新增會同時展開該區）；
   代碼或名稱留白 → 頂部紅字提示「第 n 筆…未填代碼」、儲存鈕停用；補齊後可儲存。
6. 同一列的代碼與名稱都填「21」「機械群」（與既有列完全相同）→ 驗證擋下並指出重複；
   改成同代碼不同名稱（如 `26 商業群` vs `26 商業與管理群`）→ 合法可存。
7. 「移除」任一列 → 該列消失（未儲存前可用「還原」復原）。
8. 「還原官方預設」→ 確認對話框 → 草稿被內建清單覆蓋（含剛刪掉的列），
   **按「儲存變更」後才寫入**；直接按「還原」則退回伺服器版本。
9. 儲存成功 → 過場遮罩＋綠勾視窗 2 秒後自動關閉；稽核紀錄出現 `school_codes_updated`
   （details 含類型、群別與科別筆數）。
10. 年段班級設定頁：高級中等學校班級的群別／科別代碼欄可下拉，
    選 `21` → 名稱自動帶入「機械群」；手動改成自訂名稱後再改代碼，
    **自訂名稱不會被覆寫**；輸入表外代碼（如 `ZZ`）→ 名稱留空仍可與代碼同時儲存。
11. 把代碼表改成空陣列並儲存 → 年段班級設定的下拉沒有選項，但班級編輯不受影響
    （讀取失敗同理退回內建清單）。
12. 存一次「系統設定」「單位層級設定」「校務基本資料」或「年段班級設定」
    都不會清掉代碼表（不同文件）。
