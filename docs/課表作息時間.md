# 課表作息時間（課表作息時間）

「學校基本設定」`schoolSettings`（僅超級管理員）底下的子功能，
子功能代碼 `schoolSettings.periods`。
維護每日**節次作息表**：每筆節次的主要節次代碼、節次序號、節次名稱與開始、結束時間，
含午休等非授課時段，作為日後課表、行事曆、作息公告等功能的時間依據，
內建預設即「每日八節＋午休」。

- **入口**：管理員首頁 →「學校基本設定」卡片 → 子功能入口卡片「課表作息時間」
  → `/admin/school-settings/periods`。
  「學校基本設定」頁（`/admin/school-settings`）本身是**子功能入口卡片牆**，
  版頭、權限閘門與頁尾由共用 `school-settings/layout.tsx` 提供，新增子功能＝加一張卡片＋一個子路由。
- **僅超級管理員可編輯**：頁面層由 `layout.tsx` 的 `adminModules.includes("schoolSettings")` 擋，
  伺服器層由 `requireAdminModule("schoolSettings")` 擋
  （`adminModulesOf` 對非超級一律剝除該模組），兩者同一把尺。
- **結構性資料、不按學期、全校一份**：學期轉換不會影響，也不按班級或校區分開。
- **獨立設定文件**：存 `settings/schoolPeriods`（獨立文件），不與其他設定混放；
  分支（fork）連到同一個 Firestore 即共用同一張作息表。

## 名詞

| 名詞 | 說明 |
|---|---|
| 主要節次代碼 | 節次的識別代碼，**全校唯一**（內建預設 `P1`…`P8`，午休為 `N`） |
| 節次 | 節次序號，0～99 的整數、**全校唯一**；`0` 保留給午休等非授課時段，1 以上為授課節次 |
| 節次名稱 | 顯示名稱（如「第一節」「午休」），必填 |
| 課表作息時間 | 本設定的內容：一張每日作息表，每筆為 `{ 代碼, 節次, 名稱, 開始時間, 結束時間 }` |
| 非授課時段 | 不上課的時段（如午休）：節次序號填 `0`，仍須填寫一段起訖時間 |

## 資料模型

`settings/schoolPeriods`（獨立文件，僅超級管理員可寫）：

```
settings/schoolPeriods {
  periods: [{ code, period, name, start, end }]   // 每日作息表（上限 50 筆）
}
```

- 型別 `SchoolPeriodsSetting`、`SchoolPeriodRow`；常數
  `PERIODS_DOC_ID = "schoolPeriods"`、`PERIODS_MAX_ROWS = 50`、`PERIODS_CODE_MAX = 20`、
  `PERIODS_NAME_MAX = 40`、`PERIODS_MIN_NUMBER = 0`、`PERIODS_MAX_NUMBER = 99`
  （`src/types/school-periods.ts`）。
- **列沒有 `id`**：順位＝陣列順序（畫面依陣列顯示），識別靠 `code` 與 `period` 兩個唯一欄位。
- `start`／`end` 為 `HH:MM`（24 小時制補零），如 `08:00`、`17:10`。
- `readSchoolPeriods(raw)` 寬容讀回：逐筆去空白，代碼或名稱留白、節次非整數、
  時間格式不符者丟棄；`periods` 不是陣列或文件不存在 → 回內建預設。
- 內建預設 `defaultSchoolPeriods()`：**每日八節＋午休**（新環境畫面立刻可用）。

| 主要節次代碼 | 節次 | 節次名稱 | 開始時間 | 結束時間 |

## API

`src/app/api/admin/school/periods/route.ts`

| 方法 | 行為 |
|---|---|
| `GET` | 讀回 `{ setting }`；`setting` 經 `readSchoolPeriods(...)` 寬容修正（文件不存在＝內建預設） |
| `PUT` | body `{ setting }`，整份覆寫 `settings/schoolPeriods`（白名單寫入 `periods` 五欄）；以 `validateSchoolPeriods` 驗證，不過即 400 且不寫入；回 `{ setting }` |

- 守門：`requireAdminModule("schoolSettings")` —— `adminModulesOf` 對非超級一律剝除
  該模組，因此等同「僅超級管理員」，與頁面層判斷同一把尺。
- 其他：`assertSameOrigin`、限流 `SCHOOL_PERIODS_GET`（60/分）／`SCHOOL_PERIODS_MUTATE`（20/分）、
  稽核 `logActivity("school_periods_updated")`（details 記節次筆數）、
  `Cache-Control: no-store`、`MAX_BODY = 400,000`。
- **快取**：讀取走 `cachedSettingDoc` 30 秒快取，PUT 成功後
  `invalidateAdminListCache()` 失效（`docs/資料庫讀取規範.md` 鐵律 5、6）。

## 伺服器驗證規則

`validateSchoolPeriods(raw)`（API 與表單共用，任一不過即 400，**整份不寫入**）：

<details>
<summary>驗證規則七條</summary>

1. `raw` 必須是物件（非陣列、非 null），`periods` 必須是陣列，筆數 ≤ 50。
1. 逐筆：欄位必須是物件；`code`、`name`、`start`、`end` 都必須是**文字**。
1. 欄位必填與長度：`code` 去頭尾空白後必填 ≤ 20 字、`name` 必填 ≤ 40 字。
1. `period` 必須是 **0～99 的整數**（0 為非授課時段），且**不得重複**；
   `code` 也不得重複。
1. `start`／`end` 必須是 `HH:MM`（24 小時制），且**結束時間必須晚於開始時間**。
1. **時段不得重疊**：依開始時間排序後相鄰比對，交疊即擋下
   （訊息含兩筆名稱與起訖時間）。
1. 錯誤訊息帶列序號（如「第 3 筆未填主要節次代碼」），可直接對照畫面。

</details>

## 介面

`src/components/SchoolPeriodsEditor.tsx`，沿用其他學校基本設定子功能的
**saved／draft** 模式（未存變更可用「還原」放棄、驗證不過儲存鈕停用），
儲存結果用 `Toast` 浮動訊息（2 秒自動關閉）。

**頂部列**：左側筆數說明「共 n 筆（上限 50 筆）」，右側三個按鈕：

1. **新增一列**：表尾加一列空白（代碼／名稱／時間留空、節次待填），達上限 50 筆停用。
1. **還原**：放棄未存變更（無變更時停用）。
1. **儲存變更**：未變更或驗證不過時停用。

**表格**：欄位 `主要節次代碼｜節次｜節次名稱｜開始時間｜結束時間｜操作`，
`操作` 為**上移／下移／移除三個 SVG 圖示按鈕**（`OrgUnitTable` 同款樣式與路徑）：

1. **上移／下移**（SVG 箭頭）：與相鄰列對調順位，陣列順序即畫面與儲存順序；
   第一列的上移、最後列的下移停用。
1. **移除**（SVG 垃圾桶）：刪掉該列，未儲存前可用「還原」復原；
   純草稿編輯，不另開確認視窗。

時間欄用原生 `<input type="time">`、節次用 `type="number"`（0～99）、
代碼與名稱為文字框（分別限 20／40 字）；表格過寬時以外層 `overflow-x-auto` 橫向捲動。
空白列照常顯示，但留白或格式不符時頂部與底部各顯示一次紅字提示、儲存鈕停用。

## 與其他功能的關係

- **目前尚無取用點**：本設定先落地為全校作息的單一事實來源，
  日後課表、行事曆行程、作息公告等應從這裡取用，避免各處各自寫死時間。
- **與樓層空間設定同層**：兩者都是結構性資料、都不按學期；
  空間管「在哪裡」，本設定管「什麼時間」。
- **不與其他設定混放**：`settings/schoolPeriods` 與 `settings/system`、`settings/school`、
  `settings/schoolProfile`、`settings/schoolClasses`、`settings/schoolCodes`、
  `settings/spaces` 各自獨立文件，任一方的整份覆寫都不會清掉本資料。
- **不變項**：超級屬性的層級守門、`schoolSettings` 超級專屬、
  `settings/system` 的覆寫行為，皆不因本功能改變。

## 驗收清單

<details>
<summary>驗收九項</summary>

1. 一般管理員看不到「學校基本設定」卡片；直開 `/admin/school-settings/periods`
   顯示「權限不足」；`GET/PUT /api/admin/school/periods` 回 403。
1. 超級管理員由「學校基本設定」入口卡片（「課表作息時間」）進入本頁 →
   **新環境（文件不存在）直接顯示內建預設**：第一節 08:00–08:50 … 第四節 11:20–12:10、
   午休 12:40–13:10、第五節 13:20–14:10 … 第八節 16:20–17:10，共 9 筆。
1. 狀態列顯示「已與伺服器同步」；改任一欄 → 顯示「有尚未儲存的變更」且儲存鈕啟用。
1. 節次留空或填 100 → 紅字提示「第 n 筆的節次必須是 0～99 的整數」、儲存鈕停用；
   補齊後可儲存。
1. 兩列填相同主要節次代碼（或相同節次序號）→ 驗證擋下並指出重複。
1. 結束時間早於開始時間、或兩筆時段交疊 → 驗證擋下
   （重疊訊息含兩筆名稱與起訖時間）。
1. 「新增一列」→ 表尾多一列空白；「移除」（SVG 垃圾桶）任一列 → 該列消失
   （未儲存前可用「還原」復原）；「上移／下移」（SVG 箭頭）→ 與相鄰列對調，
   第一列上移、最後列下移為停用狀態；儲存後重新整理順序仍在。
1. 儲存成功 → Toast「課表作息時間已儲存」2 秒後自動關閉；重新整理頁面資料仍在；
   稽核紀錄出現 `school_periods_updated`（details 含節次筆數）。
1. 存一次「系統設定」「單位層級設定」或「樓層空間設定」都不會清掉作息表（不同文件）。

</details>

## 待辦（本輪未做）

- 課表、行事曆行程、作息公告尚未串接本設定（目前僅提供維護入口）。
- 節次的跨日排序、體育連堂或彈性調課等特殊時段（同節次多段）尚未支援。
- 依學期或學制（日間部／夜間部）分張作息表尚未支援（現為全校一份）。
