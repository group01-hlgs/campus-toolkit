# 行事曆功能模組規劃書

> 本文件為「行事曆」功能模組的研發規劃，契約設計依據 `主程式模組與功能模組.md` §6.2，
> 資料模型以 `資料模型.md` 為準，Firestore 讀取遵循 `資料庫讀取規範.md` 六鐵律。

## 1. 設計決策

| 項目 | 決定 | 說明 |
|---|---|---|
| 顯示範圍 | **全校可見** | 所有身分（學生／家長／教職員／管理員）皆可看到 active 行程；取消（cancelled）不顯示 |
| 行程欄位 | **基本欄位＋全天＋重要性＋提醒** | 標題、說明、地點、開始/結束時間、全天/跨日、重要性標記、個人提醒 |
| 提醒功能 | **個人提醒** | 比照公告提醒模式（非推播，開啟頁面才更新）；集合 `calendarReminders` |
| 跨模組掛勾 | **提供 `publishScheduleFromModule()`** | 含 upsert 語意（同 `sourceModule+sourceRef` 再呼叫＝覆寫更新） |
| 權限模型 | **學生/家長＝唯讀；教職員/管理員＝可建立** | 教職員可建立行程；管理員可建立＋編輯＋取消所有行程 |

## 2. 資料模型

### 2.1 `calendarEvents` 集合

> 刻意不放 `settings/*`——行程資料混入會被整份覆寫抹掉（同 `announcements` 的既有決策）。

```ts
interface CalendarEventRecord {
  id: string;
  title: string;                   // ≤ 120 字，必填
  description?: string;            // ≤ 2000 字
  location?: string;               // ≤ 120 字
  startAt: number;                 // epoch ms，必填
  endAt?: number;                  // epoch ms；缺省＝單點事件
  allDayDate?: string;             // "YYYY-MM-DD"；全天事件用（與 startAt 二選一）
  important: boolean;              // 重要性標記（預設 false）
  sourceModule: string;            // 必填：來源模組代碼；行事曆自己建＝"calendar"
  sourceRef?: string;              // 來源資料 id（如預約單號），改期/取消靠它定位
  audience: {                      // 同公告受眾形狀
    roles: UserRole[];             // 至少一個（閱讀權限「無」時由系統補為四身分，供 array-contains 命中）
    classCodes: string[];          // 空陣列或含 "*"＝不限班級
  };
  isPublic: boolean;               // 閱讀權限「無」＝公開：不需登入即可查閱（與身分選項互斥，公開時一律全校）
  status: "active" | "cancelled";  // 取消＝預設保留文件、不顯示（供對帳）；「下架行程真實刪除」開啟時改為連同提醒刪除
  createdBy: { uid: string; name: string; role: UserRole };
  publishUnit?: string;              // 發佈單位（如：教務處）；教職員建立時預帶名冊「單位」，可改
  academicYear?: number;
  semester?: 1 | 2;
  createdAt: number;
  updatedAt: number;
}
```

**Firestore 欄位拉平**（比照公告）：
- `audienceRoles: string[]`＋`audienceClassCodes: string[]`，以便 `array-contains` 查詢
- `isPublic: boolean` 與上述同層（與 `audience` 內其他欄位一起讀寫）

**閱讀權限（比照公告「無＝公開」）**：管理表單標示「閱讀權限」，可選「無（公開，不需登入即可查閱）」
或勾選身分（可多選），兩者互斥；勾「無」時 `isPublic=true`、`roles` 由系統補為四身分、班級一律全校。
免登入可讀判定 `isCalendarEventPublicReadable(record)`＝`isPublic && !班級限定`：
- `surface=login`（系統首頁）只回公開行程；單筆行程頁 `GET /api/calendar/[id]` 公開行程免登入；
- 勾滿四身分**不算**公開（須登入）；各身分頁仍以 `array-contains role` 命中（公開行程 roles 含全身分）。

### 2.3 設定：`settings/calendar` 單文件

| 欄位 | 型別 | 預設 | 說明 |
|---|---|---|---|
| `categories` | `CalendarCategory[]` | 學期初/期中/期末/活動/其他 | 行事曆類型（可排序、啟用/停用）；UI 標示為「行程類型」 |
| `defaultRemindersEnabled` | `boolean` | `true` | 是否啟用個人提醒功能 |
| `surfaces` | `Record<login\|student\|parent\|staff\|admin, { enabled, limit }>` | 5 處皆 `true`、`limit: 5` | 5 個顯示位置的顯示與否＋可翻頁則數（管理於「顯示位置」卡片；limit 預設 5、省 Firestore 讀取量）；顯示方式統一：標題右側固定放「進入行事曆」入口 SVG（連各身分行事曆功能首頁 `/{身分}/calendar`，系統首頁未登入連回首頁 `/`），有 2 則以上尚未結束（含今天）行程時行程列右側加上下箭頭逐則翻頁（一次顯示 1 條，標題連單筆行程頁 `/calendar/[id]`，跳出新頁；翻到盡頭再按箭頭改為「前往行事曆」連結），沒有則只顯示入口；行動版（<sm）日期｜類型與標題各佔一行 |
| `policies` | `{ hardDeleteCancelled: boolean }` | `false` | 行程原則（管理於「規則設定」卡片）：下架（取消）行程連同 `calendarReminders` 真實刪除；關閉＝保留文件僅隱藏 |

**後備類型（刪除機制）**：`other`／「其他」為後備類型，不可刪除、不可停用（`readCalendarSettings`／
`saveCalendarSettings` 皆以 `ensureFallbackCategory()` 強制存在且啟用）。管理端刪除其他類型時
**不做批次遷移**（省 Firestore 讀寫額度），既有行程的 `categoryId` 會暫時失效，以「讀取時後備」兜住：

1. 顯示：`resolveCategoryName()`（`types/category.ts`）依序取 原 id → 後備類型名稱 → 預設名稱，永不露出原始 id；
   API 回傳的 `categoryName` 即為解析後名稱，前端優先採用。
2. 編輯：表單 `categoryId` 經 `normalizeCategoryId()` 正規化，失效即自動歸入「其他」並提示
   「原類型已刪除」，按下儲存的那一筆才被修正（一次一筆）。
3. 新增：預設值指向後備類型（後備類型必啟用），不再產生新的失效引用。

公告分類（`settings/announcements`）採同一機制，後備分類為 `other`／「其他」（預設分類清單亦含「其他」）。

## 4. 跨模組掛勾：`publishScheduleFromModule()`

### 4.1 介面

```ts
// 建立；同 sourceModule + sourceRef 再呼叫＝覆寫更新（upsert）
const { id, updated } = await publishScheduleFromModule({
  sourceModule: "spaceBooking",   // 必填
  sourceRef: booking.id,          // 強烈建議填：改期/取消靠它定位
  title: "...",
  description: "...",
  location: "...",
  startAt: Date.now(),
  endAt: Date.now() + 3600_000,
  important: false,
  audience: { roles: [...], classCodes: [...] }, // 必填、明確
  status: "active",               // 取消時傳 "cancelled"
});
```

### 4.2 契約條文

1. 只寫 `calendarEvents` 集合；校驗失敗拋錯（title 非空、時間合法、閱讀權限非空——「無」＝`isPublic` 屬合法）
2. `sourceModule` 必填；**有 `sourceRef` 時以 `sourceModule+sourceRef` 定位**：
   存在→覆寫欄位（`updatedAt` 遞增），不存在→新建。無 `sourceRef` 每次皆新建
3. `status: "cancelled"` **保留文件**（不刪除），供來源模組對帳
4. 寫入後內建 `invalidateCalendarCache()`（清 `calendar:` 前綴讀快取）
5. 取消/過期事件**不回給任何讀取端**

## 5. 讀取契約（過濾下推＋快取）

依 `資料庫讀取規範.md` 鐵律 2/3/6：

- **查詢條件全下推**：`status == "active"` ＋ 時間範圍（`startAt >=` 從今日零時）
- **班級過濾**：受眾含班級時於記憶體過濾（量級同公告，避免複合索引）
- **快取**：`cachedRead("calendar:<role>:<classCode>:<range>", 15_000, ...)`
  （顯示位置另用 `calendar:surface:<surface>:<role>:<classCode>:<take>`，同一前綴）
- **寫後失效**：`invalidateCalendarCache()` 清 `calendar:` 前綴

## 6. API 路由設計

### 6.1 使用者端

| 路徑 | 方法 | 守門 | 說明 |
|---|---|---|---|
| `/api/calendar` | GET | `verifySession` | 各身分行事曆列表（role＋時間範圍過濾） |
| `/api/calendar` | POST | staff/admin | 教職員建立行程 |
| `/api/calendar/[id]` | GET | 公開行程免登入；其餘 `verifySession` | 單則行程內容 |

| `/api/calendar/reminders` | POST | `verifySession` | 切換提醒（toggle） |
| `/api/calendar/surface` | GET | `verifySession`（`surface=login` 免登入） | 顯示位置的未結束行程前 N 則（N＝該位置顯示筆數設定，預設 5） |

### 6.2 管理端

| 路徑 | 方法 | 守門 | 說明 |
|---|---|---|---|
| `/api/admin/calendar` | GET | `requireAdminModule("calendar")` | 管理端清單（含已取消；`policies.hardDeleteCancelled` 時先批次清除下架行程） |
| `/api/admin/calendar` | POST | `requireAdminModule("calendar")` | 建立行程 |
| `/api/admin/calendar/[id]` | GET | `requireAdminModule("calendar")` | 讀取單則（編輯用） |
| `/api/admin/calendar/[id]` | PATCH | `requireAdminModule("calendar")` | 更新行程（下架原則開啟時＝真實刪除） |
| `/api/admin/calendar/[id]` | POST | `requireAdminModule("calendar")` | 取消／恢復行程（下架原則開啟時＝真實刪除） |
| `/api/admin/calendar/settings` | GET | `requireAdminModule("calendar")` | 讀取模組設定 |
| `/api/admin/calendar/settings` | PUT | `requireAdminModule("calendar")` | 儲存模組設定 |

## 7. 頁面結構

### 7.1 管理端

```
src/app/admin/calendar/
├── layout.tsx   # AdminSectionShell(moduleKey="calendar", title="行事曆", ...)
└── page.tsx     # 管理頁本體
```

**管理頁內容**（「設定管理」卡片內含三張子卡片，全部預設收合）：

- 顯示位置（5 處顯示與否：系統首頁／學生／家長／教職員／管理員；顯示方式統一）
- 行程類型（類型管理、預設提醒開關）
- 建立／編輯行程表單（可收合；含「發佈單位」欄，「發佈者」＝建立者自動帶入）
- 行事曆清單（月份切換、列表檢視、搜尋、狀態篩選；含發佈單位／發佈者欄；下架原則開啟時按鈕標示「下架」）

### 7.2 各身分頁面

```
src/app/student/calendar/page.tsx   # <RoleLayout role="student"><CalendarView role="student" /></RoleLayout>
src/app/parent/calendar/page.tsx    # 同上（parent）
src/app/staff/calendar/page.tsx     # 同上（staff，canCreate）
```

**單筆行程頁**：`src/app/calendar/[id]/page.tsx`（顯示位置行程列「跳出新頁」用，版面比照
`/announcements/[id]`）。資料 `GET /api/calendar/[id]`——**公開行程免登入可讀**（閱讀權限「無」＝
`isPublic`，同 `surface=login` 的公開規則，見 §2.1）；其餘行程須登入（401 →「請先登入」＋回首頁按鈕）
且依身分／班級判定（403 →「無權限閱讀此行程」），不存在或未生效回 404 →「查無此行程」。

### 7.3 共用元件：`CalendarView`

**功能**：
- 月曆檢視（月曆格＋當日行程列表）
- 列表檢視（依日期排序的行程清單）
- 重要性標記（星號圖示）
- 個人提醒切換（「提醒我」按鈕）
- 字級切換（小/中/大，localStorage）
- 教職員可見「建立行程」按鈕

## 10. 相容性檢查清單

依 `主程式模組與功能模組.md` §7：

1. **Firestore 讀取六鐵律**：過濾下推、精準查詢、禁 N+1、同請求復用、快取＋寫後失效
2. **fail-safe 一律朝「關」**：閘門 fail-closed
3. **超級管理員 bypass** 只在可見性層，不繞過資料寫入驗證
4. **`settings/system` 覆寫保留**：新增同類欄位時一併加入保留清單
5. **Next.js 版本注意**：動程式碼前先讀 `node_modules/next/dist/docs/`
6. **CSP 無需為模組變更**：模組走同源路由
7. **交付流程**：`npm run lint` → `npm run version:bump` → commit → `git push`
