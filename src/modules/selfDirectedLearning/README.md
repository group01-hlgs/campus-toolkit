# 自主學習計畫（selfDirectedLearning）

選用功能模組（外掛），掛載於 `campus-toolkit` 主程式。依 108 課綱：學校每週提供 1–3 節
彈性學習時間，學生可自由發想 6–21 週的學習方案（週次依序第 1～N 週，不綁學校行事曆、
不檢核衝堂），可安排於彈性學習時間或課餘時間完成，得邀請學校教師或相關領域人士擔任
指導教師；送出審核時才依學校現行規範調整週數並檢核場地等必填項目。

1. 開發者：[takan003](https://github.com/takan003)（`https://github.com/takan003/selfDirectedLearning`）
2. 版本：0.0.130（`contractVersion` 1、`minHostVersion` 0.580）
3. 四身分入口：管理員（設定與總覽）、學生（填報送審）、教職員（審核／兼導師瀏覽全班）、家長（檢視）

## 功能摘要

1. **文件下載／匯出服務開關**：管理規則頁可分別設定 Google Docs、Canva、Word，
   按「儲存設定」持久化；新安裝及舊設定缺少欄位時一律預設關閉。學生編輯與成果匯出的
   選單只列出開放服務，全部關閉時不顯示匯出控制，原列印功能保留。
   Word 提供真正的 .docx 下載，不需外部帳號或憑證。啟用 Google Docs／Canva 前仍須完成下方平台設定。
1. **開關檢查**：線上平台開啟匯出對話框時重新核對設定，Google Docs 在授權後、傳送內容前再核對；
   Canva 授權、回呼、匯入與工作查詢均檢查開關。沿用既有設定快取與儲存後失效機制。
   已送往外部平台的工作及既有副本不會因關閉而撤銷；Google token 為瀏覽器直接取得，
   此開關控制本網站的匯出流程，不是撤銷 Google 帳號授權。

1. **管理端**（`/admin/self-directed-learning`）：「管理規則」頁設定功能總開關（關閉即全站
   維護中）、送審起訖（僅限制送出審核，草稿與正式建立不受限）、審核起訖（審核頁顯示期限、剩餘天數與逾期提醒，僅供督促、逾期仍可審核）、週數填寫形式（全學期全填／彈性下限）、下限週數、
    文件匣件數上限（審核中＋已通過＋自行提升）、草稿匣件數上限（含退回修改）、就學期間學校審查通過最低份數（0–6 份；0＝不設定）、
   校內彈性學習節次行程（橫排上課日、直排節次的格狀勾選，取自學校課表作息）、開放場域（樓層空間建議＋可自訂；
   另可設定是否開放學生自行輸入場地）、
   審核人員名單、自主學習實施說明（給學生、家長的總說明）與自主學習計畫撰寫說明（發想新計畫、編輯草稿時顯示）。
   兩份說明都使用所見即所得編輯器（字型、字級、粗斜體底線、顏色與底色、對齊、清單、縮排、引用、清除格式），
   內容先經白名單 HTML 淨化後儲存；舊版純文字說明仍相容（自動保留換行）。
   全學期形式的週數**不人工設定**，由系統依「學校基本設定 → 學期起訖設定」的
   **上課日起訖（優先）**或學期起訖自動判斷（週日～週六為一週，未滿七日仍計一週）；
   學生自由發想時不檢核衝堂，送出審核才依此自動補齊／調整週數。
   另可設定「計畫成果撰寫截止時間」（可設定到時與分）：只適用**學校審核通過**的計畫，
   學生填寫執行成果紀錄與學習反思心得開放到此時間；自行提升的正式計畫不受此限；
   未設定＝不限制審核通過計畫的填寫期限。
2. **學生端**（`/student/self-directed-learning`）：版面為數個獨立卡片（主色頂線、明顯框線與區塊標題）：
   自主學習實施說明（預設展開，可收合）、我的計畫、撰寫計畫（發想新計畫或編輯草稿時顯示）。
   「我的計畫」分為文件匣（正式、審核中）、草稿匣（草稿、退回修改）與垃圾桶（假性刪除）三個分頁，
   附圖示與數量；草稿與退回修改可移至垃圾桶，垃圾桶可還原或永久刪除（永久刪除需二次確認，連同審查紀錄一併移除、無法復原；僅本人可操作；審核中與已通過不可刪除）；
   學生進入頁面時，垃圾桶中超過 30 天的廢棄計畫會自動永久刪除（含審查紀錄）。
   送審狀態以醒目提示條顯示「送審期間內」與完整送審期間（截止時改用警示色），
   並顯示管理端設定的審核期間。
   草稿可隨時發想與儲存，不受送審期間限制；送出審核才檢查送審期間與件數：
   同一學期可有多筆草稿，
   但**每學期僅能送審 1 份**（第一次送出後，該學期只能重送同一份；退回或抽回都算已送審），
   學校審核通過的正式計畫僅一份（送出審核一律歸為本學期，舊學期草稿送出時改記為目前學期）。
   學生也可把本學期的草稿、審核中或退回修改計畫「提升為正式」，不必等學校審核通過即可依每週時間填寫成果；
   同一學期可有多份自行提升的正式計畫；學校審核仍保留，之後被退回不影響正式狀態。
   審核中的計畫在送審期間內可「抽回修改」（警告色按鈕＋確認視窗）：抽回後回到草稿匣，
   審核人員即看不到該計畫，學生可修改後重新送出；限本學期、限送審期間，伺服器同步檢核。
   點「發想新計畫」或草稿的「編輯」才展開「撰寫計畫」表單：表單內顯示自主學習計畫撰寫說明，
   選主題與學群（教育部 18 學群下拉選單；可選「其他」自行填寫學群名稱或說明）、
   填指導老師（非必填）、
   填寫學習目標（送出審核時必填；所見即所得多行輸入，說明為「簡單扼要描述，建議採用條列陳述」，
   可見文字上限 600 字；草稿可先留白）、
   完成逐週課程安排（發想階段可選 6–21 週，週次依序第 1～N 週，不綁學校行事曆、
    不檢核衝堂、不顯示日期／節次；送出審核時由系統依現行規範自動補齊／調整週數，
    再檢查每週的學習安排與場地）、送審期間內送出審核、查看審查意見（含審核人員填寫的逐週意見）。
    場地從學校開放場域下拉選擇；管理端開放自行輸入時，可選「其他」填寫自訂場地名稱。    學習安排使用零依賴所見即所得編輯器（字型、字級、粗斜體底線、文字顏色與底色調色盤、
    靠左／置中／靠右對齊圖示、清單、縮排、引用、刪除線、清除格式），內容先經白名單 HTML 淨化後儲存；可見純文字上限 600 字。
    逐週安排以表格呈現（第一欄為週次，第二欄合併學習安排與場地，
    場地位於學習安排輸入框上方、水平靠左對齊），
    每週第一欄底部（下面還有一週時）有向下箭頭，可將本週學習安排與場地完整複製到下一週。
    草稿可分次儲存（未填完不擋），送出審核時自動調整週數並要求每一週的學習安排／場地皆填妥。
    撰寫表單頂部與底部都有加大的「儲存草稿／送出審核」按鈕，長表單不必捲到底。
    撰寫時畫面左側有兩個跟隨捲動的浮動圖示：快速儲存草稿與列印預覽；
    點列印預覽可在新分頁以 A4 紙張樣式檢視目前編輯內容（含尚未儲存的變更）並列印；
    列印表頭包含學習目標（富文本），逐週表格與頁首頁尾維持原樣；
    列印輸出只保留紙張內容，按鈕、浮動圖示與陰影（含瀏覽器擴充套件注入的浮動面板）都不會被帶進 PDF。
   週數上限為 21 週（自由發想 6–21 週）；送出審核時依學校規範自動調整。
   「查看計畫與撰寫成果」與教職員審核頁一致：先顯示學習目標，逐週安排以表格呈現（表頭週次／學習安排／場地
   水平置中；週次欄垂直置中並列出週次、時段），逐週審查意見接在該週列下方。
   計畫通過審核或學生自行提升為正式後，「查看計畫與撰寫成果」的每一週列下方會多一塊「執行成果紀錄」（可單週收合／展開，
   預設收合；左側另提供浮動 SVG 按鈕可一次展開或收合全部，以及儲存成果）：每一週要等該週規劃時間
   （最後一個節次結束）過了才開放填寫，可由學生補寫先前週次；最後一週時間過了之後再開放
   「學習反思心得」。兩者都只開放到管理端設定的「計畫成果撰寫截止時間」（可設定到時與分），
   並以「儲存執行成果紀錄」按鈕一次儲存（所見即所得，可見文字上限 2000 字）。
   同一區塊上下都有「預覽列印（計畫與成果）」：按鈕旁可勾選成果紀錄呈現方式「分開式」（預設，另列於表格下方）
   或「融入式」（以跨「學習安排／場地」兩欄的獨立列併入當週）；以 A4 紙張樣式列印正式計畫內容、
   逐週執行成果紀錄與學習反思心得，週次欄列出週次與時段（沿用撰寫表單的列印預覽頁，於新分頁開啟）。
3. **教職員端**（`/staff/self-directed-learning`）：受指定審核人員通過／退回（退回必填意見）；
   審核頁**只顯示送審中（`submitted`）的計畫**，其他狀態不顯示；兼導師且非審核人員者才可瀏覽全班計畫。
   審核頁顯示管理端設定的審核期限、目前待審件數、剩餘天數與逾期提醒，
   每筆待審計畫顯示已等待天數以督促於期限內完成（期限僅供提示，逾期仍可審核）。
   審核佇列（兼導師另可看全班清單）採收合式摘要卡片（標題依「班號 姓名」顯示，另列主題／狀態／送出時間；
   展開後先顯示學習目標，逐週安排以表格呈現，每列為週次／學習安排／場地，
   並在每週下方提供該週審查意見），
   並提供每頁 10／20／50／100 筆分頁（純前端切片，不增加讀取）。
   逐週意見與整體意見都使用所見即所得編輯器，並各自提供 5 種常用罐頭語可快速帶入；
   退回時整體意見必填，逐週意見可留空。
   配合主程式「省流開關」：啟用時先以 count 聚合取得待審件數並顯示「顯示審核列表」按鈕，
   按下後才載入計畫內容，避免一進頁面就讀取整批待審計畫。
4. **家長端**（`/parent/self-directed-learning`）：唯讀檢視自主學習實施說明、綁定子女的計畫
   （含學習目標）、逐週安排、逐週審查意見與審查狀態。
5. **總開關維護模式**：管理端關閉總開關後，學生／教職員／家長頁面一律只顯示
   「目前此功能關閉維護中」，寫入 API 回 403；管理端不受影響，可隨時改回開啟。
6. 狀態機：草稿 → 審核中 → 已通過（鎖定）／退回修改（可改再送）；審核中可在送審期間內
   抽回修改（回到草稿）；草稿與退回修改可移至垃圾桶（假性刪除、可還原，或永久刪除；永久刪除連同審查紀錄移除；審核中與已通過不可刪除）。

## 資料集合清單（`dataCollections`，宣告即承諾）

1. `selfDirectedLearningSettings`（doc `global`）：模組設定單文件——`enabled`（功能總開關）、
   `openAt`／`closeAt`（送審期間起訖 epoch ms；僅限制送出審核）、`reviewStartAt`／`reviewEndAt`（審核起訖 epoch ms；
   null＝未設定，僅供審核頁提示與督促）、`weekMode`（`full` 全學期全填／`flexible` 彈性
   下限）、`minWeeks`（彈性下限週數）、`maxDocumentPlans`（文件匣件數上限，審核中＋已通過＋自行提升；正整數，無硬上限）、
   `maxDrafts`（草稿匣件數上限，含退回修改；正整數，無硬上限）、
   `minApprovedPlans`（就學期間學校審查通過最低份數；0＝不設定，0–6 份）、`slots`（節次行程）、`venues`（開放場域）、
   `venueEditable`（是否開放學生自行輸入場地名稱；false＝只能從 `venues` 清單選擇，送審會檢查）、
   `reviewers`（審核人員 uid＋名稱）、`instructions`（自主學習實施說明；淨化後 HTML）、
   `writingInstructions`（自主學習計畫撰寫說明；淨化後 HTML）、`updatedAt`。
   **不存全學期週數（`maxWeeks` 已移除）**：全學期形式的週數由主程式上課日／學期起訖自動推算
   （週日～週六為一週，台灣學校通常為 21 或 22 週）。
2. `selfDirectedLearningPlans`：學生計畫（doc id＝`{學年學期}_{uid}_{時間亂數}`；舊資料
   `{學年學期}_{uid}` 仍相容）——主題、學群、指導老師、學習目標（`learningGoals`，淨化後 HTML；
   送出審核時必填）、逐週安排（`weeks[]`：週次／內容／
   場地／時段；`content` 為淨化後的 HTML，舊版純文字仍相容）、`executionRecords[]`
   （逐週執行成果紀錄：`week`／`note`，淨化後 HTML）、`reflection`（學習反思心得，淨化後 HTML）、
   身分欄（班級等）、`status`、
   `deletedAt`（移至垃圾桶的時間；null＝不在垃圾桶）、`submittedAt`、
   `selfApprovedAt`（學生自行提升為正式的時間；null＝未提升）、
   `parentVisible`（是否開放家長檢視；預設 true，舊資料沒有此欄位時視為開放）、
   `firstSubmittedAt`（第一次送審時間，不再清除；用於「每學期僅能送審 1 份」）、`updatedAt`。同一學生同一學期
    可有多筆草稿；**每學期僅能送審 1 份**（第一次送出後只能重送同一份，退回或抽回都算已送審）；
    學校審核通過的正式計畫（`approved`）僅一份，
    但可有多份由學生自行提升的正式計畫（`selfApprovedAt` 有值）；
    送出審核一律歸為**本學期**（舊學期草稿送出時寫入目前學期），送審、學生自行提升與審核通過時都會檢查。
3. `selfDirectedLearningReviews`：審查意見（計畫 id、審核者、`decision`、整體 `note`、
   逐週 `weekNotes[]`（`week`／`note`，皆為淨化後 HTML）、`reviewedAt`；保留多輪歷程）。
4. `selfDirectedLearningLocks`：「學生＋學期」鎖定文件（doc id＝`{學年學期}_{uid}`）——
   `submittedPlanId`（目前審核中的計畫）、`approvedPlanId`（已通過的正式計畫）、`updatedAt`。
   送出審核、抽回、通過／退回都在 transaction 內讀寫同一份文件，讓同一學生同一學期的狀態轉換
   序列化，杜絕同時送審／同時通過的競態；沒有鎖定文件的舊資料仍以計畫清單掃描把關。

## 掛勾需求（`hooks`）

1. `announcements`（公告）：管理端**儲存設定**時以 `publishFromModule`／`updateFromModule`
   同步一則「自主學習計畫送審期間」公告（固定 `sourceRef: "open-window"`，重複儲存只更新不
   重複發文；清空送審時間即 `archived` 撤回）。
2. `calendar`（行事曆）：同步一筆行程（`publishScheduleFromModule` 同 `sourceRef` 覆寫更新；
   清空送審時間即 `cancelled`）。另**唯讀**行事曆行程的「學校活動層級」，比對逐週彈性學習時間
   是否衝堂（只比對涵蓋該學生年級／班級或全校的活動，不寫入行事曆）。
3. 兩者皆失敗**不阻擋**設定儲存——API 回 `hookWarning`，頁面以 Toast 提示。

## 安裝後設定方式

1. 安裝模組後至「功能模組管理」（`/admin/modules`）**啟用**本模組（預設未啟用，fail-safe 朝關）。
2. 為管理端指派本模組權限單位（`selfDirectedLearning`，權限類別「校務資料」）。
3. 開啟「管理規則」（`/admin/self-directed-learning`）：設定功能總開關、送審起訖、審核起訖、週數填寫
   形式與全學期／下限週數、文件匣與草稿匣件數上限、就學期間學校審查通過最低份數、節次行程、場域、審核人員與說明並儲存（儲存即同步公告與行事曆）。
4. 草稿可隨時發想；送出審核需在送審期間內。教職員審核資格來自第 3 步的審核人員名單（管理員恆可審）。
   總開關關閉期間，非管理端一律只見「目前此功能關閉維護中」，資料不受影響。

## Google Docs 匯出（第一階段）

管理規則頁提供預設收合的「Google Docs／Canva 匯出：啟用準備與設定」，
供管理人員查閱平台後台、環境變數、本機與正式回呼及常見問題；
此區只顯示通用說明，不讀取、顯示或儲存部署憑證。

1. 學生撰寫表單與正式計畫的成果操作列提供「匯出格式／平台」下拉選單，選擇 Google Docs
   後按「匯出」。另提供 Canva 匯入與 Word（.docx）下載；預覽列印與成果分開式／
   融入式保留，匯出亦沿用目前選擇的呈現方式。
1. 每次 Google Docs 匯出須確認資料傳送並主動選擇自己的 Google 帳號；建立的是當下的可編輯副本，
   包含畫面中尚未儲存的計畫、逐週成果及心得。外部編輯不回寫校內、不改變審核狀態、
   不自動公開分享；每次重做會建立新文件，請保留成功視窗中的文件連結或於自己的 Drive 查找。
1. 匯出確認視窗提供「文件風格」下拉選單：基本款（接近網頁內容，不加裝飾配色）、
   清爽正式（預設，深藍標題與淺藍表頭）、黑白簡約（灰階、方便列印）、
   作品集（深綠配色與較多留白）。各風格保留相同內容、基本文字格式及可編輯表格，
   沿用成果分開式／融入式；不另提供剪貼簿按鈕。
   既有文件不會自動更新，需重新匯出建立新版副本。
   Google 轉檔後字型、分頁可能不同；不保證與列印預覽逐頁相同。
   校內不保存 Google 文件網址或憑證，未新增 Firestore 讀寫。存取 token 僅在此次操作的
   記憶體中使用，不寫入 cookie、瀏覽器儲存空間或校內伺服器。

<summary>Google Cloud 設定與故障排除</summary>

1. 使用主程式既有的 `NEXT_PUBLIC_GOOGLE_CLIENT_ID`（OAuth 網頁應用程式用戶端 ID，

1. OAuth 用戶端的「已授權的 JavaScript 來源」加入實際網站 origin（本機為
   `http://localhost:3000`）；此流程採 Google Identity Services token model，不需要新增
   OAuth callback route 或 redirect URI。
1. OAuth 同意畫面加入 `https://www.googleapis.com/auth/drive.file`，依 Google 規定設定
   應用程式受眾、發布狀態、測試使用者與必要的驗證。僅請求此應用程式建立／開啟之檔案權限，
   不要求讀取整個 Drive；不儲存 refresh token。
1. 學校 Workspace 若限制第三方應用程式，須由管理員允許此用戶端及權限；
   使用者拒絕授權、學校封鎖、未啟用 API 或 popup 被擋時，系統會明確顯示失敗，不改下載其他格式。
1. Google 拒絕建立文件時，會依原因顯示簡短中文處理提示，區分 API 未啟用、空間不足、
   權限不足、學校政策或配額問題，不顯示原始長訊息或錯誤代碼。
1. 網路中斷、逾時或異常回應不自動重試，以免重複建立。請先檢查自己的 Google Drive，
   確認是否已有副本後再決定是否重做；分享設定沿用 Google／學校政策，程式不修改 permissions。

## Word 下載（第三階段）

1. 管理人員在「文件下載／匯出服務」開啟 Word 並儲存，學生重新載入頁面，
   選擇「Word（.docx）」、按「匯出」，選擇四種文件風格之一，再按「下載 Word（.docx）」。
   不需 Microsoft、Google 或 Canva 帳號授權；三個服務開關仍預設全部關閉。
1. 下載為原生 OOXML／ZIP 格式，不是改副檔名的 HTML。包含學生姓名、班級、計畫、
   逐週安排、成果及心得與畫面中尚未儲存的內容，支援成果分開式／融入式。
   保留基本粗斜體、底線、刪除線、換行與可編輯表格；清單轉為項目文字，
   不保證保留所有原始字型、文字顏色與分頁，請用 Word 或相容軟體確認。
1. 校內伺服器即時產生並回傳，不另存匯出內容、不傳送第三方、不更動原計畫。
   檔名會移除不適合下載的控制字元與特殊符號；收到成功提示後請查看瀏覽器下載項目。
   身分、模組與 Word 開關於下載請求時驗證，另有 CSRF、請求大小及限流限制。
   Word 不另發下載前的檢查請求；連線失敗會顯示中文提示並保留下載按鈕供手動重試。

## Canva 匯出（第二階段）

1. 在相同的「匯出格式／平台」選單選 Canva，選擇文件風格並確認資料傳送後，按
   「授權 Canva 並匯入」。登入自己的 Canva 帳號並同意權限，返回原視窗等待匯入，
   完成後按「開啟 Canva 設計」。若 Canva 產生多份設計，會逐一提供連結。
1. Canva 不接受 HTML 匯入，因此由後端將此次快照產生為標準 DOCX，再以官方
   Design import API 上傳；保留基本粗體、斜體、底線、刪除線、換行與可編輯表格，
   清單轉為項目文字。四種風格提供基礎配色與字級，不保證 Canva 保留全部原始富文字樣式、
   字型與分頁；Google Docs、Word 下載與校內列印不受影響。
1. 不自動公開分享、不回寫校內，也不額外讀取或儲存計畫文件。既有登入與模組啟用檢查
   沿用宿主。授權碼僅供後端交換；secret、access token 不回傳前端 JSON、不記錄到 log。
   PKCE verifier、token、工作識別以使用者及用途綁定的加密 HttpOnly／SameSite=Lax cookie
   暫存，最多 10 分鐘（HTTPS 使用 Secure），不保存 refresh token、不新增 Firestore 集合。

<details>
<summary>Canva 開發者與部署設定</summary>

1. 在 [Canva Developer Portal](https://www.canva.com/developers/) 建立應用程式，
   啟用 Outside Canva 的 Canva REST APIs；公開讓學生使用前，依 Canva 當時規定完成
   審核／發布與測試人員設定。Private 應用程式有 Enterprise 團隊限制，不等同一般校內網站。
1. Scopes 只選 `design:content:write`。Redirect URLs 加入
   `http://127.0.0.1:3000/api/student/self-directed-learning/canva/callback`。
   本機請從 `http://127.0.0.1:3000` 開啟網站並重新登入；
   不要從 localhost 開始後回到 127.0.0.1，兩者 cookie 不共用。
   伺服器以 Host／代理來源標頭核對 origin，避免 Next.js 正規化 loopback URL 造成誤判。
1. 在宿主 `.env.local` 設定 `CANVA_CLIENT_ID`、`CANVA_CLIENT_SECRET`、
   `CANVA_REDIRECT_URI`，後者須與 Developer Portal 的回呼網址完全一致。
   不使用 `NEXT_PUBLIC_` 前綴，不提交 secret；修改後重啟 dev server，部署時重建。
   並確保宿主 `SESSION_SECRET` 至少 32 字元，供用途隔離的 cookie 加密金鑰衍生。
1. 正式環境改為學校 HTTPS origin 加上相同回呼路徑；授權起點與回呼須同 origin。
   若原有 Google 登入需支援本機 127.0.0.1，亦須在該供應者允許該來源，
   或使用既有帳密登入。Google Docs 的用戶端 JavaScript 來源設定與 Canva 分開。
1. 授權等待最多 3 分鐘，可按取消；匯入送出後最多輪詢 2 分鐘，期間不重送匯入。
   逾時／斷網／未知結果時先查看自己的 Canva 專案，再決定是否重新匯出，避免重複建立。
   授權有效期短，逾時請重新操作；同一瀏覽器請勿同時進行多個 Canva 匯出。
1. 所有匯入與查詢走後端固定 Canva API 網址，無須放寬宿主 CSP；
   不提供公開文件下載 URL，不額外列出學生既有設計。文件快照上限 1 MB、53 週。

</details>

參考：[Canva OAuth](https://www.canva.dev/docs/apps/rest-apis/authentication/)、
[Design import](https://www.canva.dev/docs/apps/rest-apis/reference/design-imports/)。
回歸測試沿用上方 `test-document-export.mjs`，使用合成資料與模擬 Canva API，
不以學生資料自動呼叫外部服務。
